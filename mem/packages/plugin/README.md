# @avantf/dsh-mem

DSH（DeepSeek Harness）原生记忆插件：给 agent 一份可长期检索的**记忆**和一个**文档知识库**——
它跨会话记得你说过的事，也能把文档收进库里按语义查回来。装上后提供 8 个模型工具、三段用法提示
和两个主窗口标签页（记忆 / 知识）。

## 主要功能

- **8 个模型工具**
  - `mem_remember`：新增 / 改写 / 删除事实，或对某条事实反馈有用没用（写入后立刻做矛盾检测）
  - `mem_recall`：混合检索（语义 + 全文 + 实体）、三元组方向问答、链路推理、实体探查、矛盾查询
  - `mem_admin`：列表 / 详情 / 归档恢复 / 检索统计 / 记忆保留诊断 / 向量索引诊断与修复 /
    矛盾补扫与裁决 / 维护
  - `kb_add` / `kb_list` / `kb_remove` / `kb_reindex`：新增文档（文本 / 文件 / URL，或批量导入目录，
    同名拒绝）、列表（带出受管 `.md` 的绝对路径与切片详情）、删除、重建索引；
    **改一篇既有文档就是改那份 `.md`**（用文件工具改，索引自动跟随）
  - `kb_query`：跨「记忆事实 + 文档切片」的统一检索，结果带来源标注，可据此引用原文
- **记忆与知识一起检索**：对记忆事实与文档切片做统一排序，两类结果处在同一分数刻度上，
  所以"我之前定过的约定"和"文档里怎么写的"能一次问出来。
- **记忆是活的**：按活跃使用结算，支持有效期、遗忘、去重与修订链；同一主题的改动会被识别成
  对旧事实的**修订**而不是简单叠加，写入时顺带做矛盾检测。
- **资料随手入库**：文本、本地文件、目录、URL 都能收；Markdown 按标题分块，PDF、`.docx`、`.xlsx`
  等常见格式也能直接入库（转换过程有问题会明确回报，不静默丢内容）。
- **知识可维护**：每篇文档在数据目录里留一份可编辑的 Markdown 副本，用你自己的编辑器改，
  插件会在其后自动把改动同步回索引；删除文档只删这份副本，你原来的文件不动。
- **两个主窗口标签页**（排在 对话 / 轨迹 之后）：**记忆**（浏览、编辑、归档恢复、反馈、矛盾裁决）
  与**知识**（文档列表，每行可查看切片 / 编辑 / 打开目录 / 重新摄入 / 删除；另有跨库查询与入库——
  URL / 本地文件 / 本地目录 / 粘贴文本共用一个输入）。
- 系统提示词里只加**三段**用法提示（何时该主动记忆、何时该先查记忆、何时该先查知识库 / 怎么改一篇
  既有文档）。

## 接入 dsh

```bash
# 把插件装进你要用的 profile（依赖会自动装好，不用管别的）
dsh plugin --profile <PROFILE> add @avantf/dsh-mem@<version>

# 然后重启 dsh 生效
```

版本号可以不写，但建议指定一个明确版本。

**DSH Desktop**：在「插件」页里安装同一个包即可，装完重启应用；不用动命令行。

## 怎么用

工具是给模型用的，通常不用你手写；用日常说法提要求就行。最常见的几种：

```text
记住这条：发布窗口是每周四 20:00；验收标准是灰度零回滚。
```

```text
我之前定过的数据目录约定是什么？（返回命中事实与来源）
```

```text
把 ~/docs/cgroup-v2.pdf 收到知识库的 ops 域下。
```

```text
看看知识库里关于「内存保护」的原文。
```

```text
把「每周四发布」改成「每周三发布」，并说明依据。
```

改一篇已经入库的文档：让模型"更新这篇文档"即可；也可以用任意文件工具直接编辑那份受管
`.md`（先用 `kb_list` 拿到路径），改完会自动同步，「知识」页的「重新摄入」是手动兜底。

常见维护动作：

```text
检查记忆库的检索与索引状态。
把矛盾检测的积压扫一遍，逐条裁决。
```

### 相关性门槛：严格 / 宽松

「记忆」「知识」页的查询面板有**严格 / 宽松**选择（工具面的 `mem_recall` / `kb_query` 也接受
`floors: 'strict' | 'loose'`）：

- **严格**（面板默认）：只有明确够相关的才返回，所以"没有结果"是一个可信的答案。
- **宽松**：门槛更低，用来找回边角相关的条目——仍有一条底线，不是无门槛。
- **不选时**：先按严格跑；严格档一条都没命中、且确实有条目被门槛挡掉时，自动用宽松档补跑一次，
  结果会标明「已自动放宽门槛」。门槛挡掉的空与真的没有，面板和结果里的数字能区分开。

## 配置、数据与提示词

- **数据目录**：默认 `~/.avantf`。记忆库、知识库（含受管文档副本）与模型缓存都在其中；
  环境变量 `AVANTF_HOME` 可以改变它。
- **配置**：`~/.avantf/configs/` 下的三份 YAML —— `common.yaml`（公共项，缺失时按注释模板自动创建）、
  `memory.yaml`、`knowledge.yaml`。只写你要改的项，其余取内置默认。
- **提示词文件**：`~/.avantf/prompts/` 下的 `mem-memory-usage.md`、`mem-knowledge-usage.md`、
  `mem-kb-edit.md`。缺失或为空时插件写入默认内容，**只在启动时读一次**，改完重启生效。
  可以按自己的领域改写：内置默认刻意不出现任何领域名词，只给判据与两种形状——
  - 事实型：`用户不吃香菜；订餐默认备注不要香菜。`（谁 / 什么范围 / 偏好或要求或术语是什么）
  - 规则型：`只有「注销式回购」减少总股本，库存股回购不减少——比较 EPS 影响时要区分。`
  - 不适合写进记忆：一次调查的过程叙述、数据表、命令与链接——依据归知识库文档，记忆里只留
    **结论 + 位置**（路径 / 来源 / 名称）；敏感信息同理，只记存放位置，不记明文。
- **升级前建议先备份 `~/.avantf`**：数据库迁移是单向的，用旧版本打开新库会被明确拒绝。

## 升级 / 卸载

```bash
# 升级：换版本号重装同一个包
dsh plugin --profile <PROFILE> add @avantf/dsh-mem@<version>

# 卸载
dsh plugin --profile <PROFILE> remove @avantf/dsh-mem
```

两者都要重启 dsh 生效。卸载**不动 `~/.avantf`**：记忆库、知识库、模型缓存全部保留。DSH Desktop 在
「插件」页上卸载。

## 环境要求

- **Node `>=22.15.0 <23 || >=23.11.0`**、**pnpm**
- 可选的原生加速件（分词 / 向量索引 / 本地嵌入模型）缺失时只会降低检索质量，不影响使用
