# Graphiti 清单改进项对 mem 的**功能**影响分析（基线 mem 0.5.0）

> **对象**：`GRAPHITI_COMPARISON.md` §4 的全部 19 条（G-A1–A8 / G-B1–B4 / G-C1–C3 / N1–N5）＋ §5 影响表。
> **口径**：与 `IMPROVEMENT_FUNCTIONAL_PERFORMANCE_IMPACT.md` 一致——**能力增量 / 行为变化 / 回归风险 / 触达面**；
> 本文以**功能**为主，性能只在 §6 一句话（细节见那份文档）。
> **一句话结论**：graphiti 清单的价值在**功能面扩展（时间有效性、溯源、结构接收端）与质量细节（实体归并）**，
> **不在"事实召回更精准"**——真正能提升精准度的 rerank/RRF 都被明确排除（N1–N3）。

---

## 0. 结论速览

| 类别 | 项 | 功能判断 |
|---|---|---|
| **真正新增能力** | **G-A1 + G-A2 + G-B2**（时间有效性/失效历史）、**G-A7**（溯源）、**G-A1/A6/A7/A8 + G-B1/B4**（写侧结构接收端） | mem 从"只有当前事实"变成"能表达并审计'当时是否成立'"；从"不知道这条从哪来"变成"能回答为什么记得" |
| **提升既有功能质量（非新能力）** | **G-A3 + G-A4**（实体归并）、**G-A6**（重复断言计数） | `related/probe/reason` 的实体清单更准；"被独立说过几次"从静默 no-op 变成可观测计数。**A3/A4 的先验收益可能≈0，由 spike 决定** |
| **用户可见的行为变化** | G-A6（重复 add 不再静默）、G-A8（`entity_type` 从词性变类型）、G-A2（信封多"已被取代"）、G-A7（多"来源"） | 都要进 `[0.6.0]`，且要改提示词教模型怎么读 |
| **无功能影响** | G-A5（=在办 A6，纯可解释性）、G-B3（只读派生面）、G-C1/C2/C3（不适用）、N1–N5（不做） | N1/N5 若做了反而是**功能回退**（拉平单腿强命中 / 替换掉已覆盖的一跳语义） |
| **功能上最需要警惕** | ① A 档的列若没有 B 档送内容 ⇒ **全是 NULL 的死字段**（`mirror_source` 就是先例）；② mem 已有 `status='archived'`、`supersedes_id`、trust 衰减三套"不再当前"的表达，再加 `valid_to/superseded_by` 会变成**四套**，必须写清谁优先 | |

**最重要的一条功能结论**：这批项**没有一条能直接修"3 条里 2 条不相关"**。它们的收益是
"**能回答以前答不了的问题**"（当时成立吗 / 为什么记得）与"**实体类查询更干净**"，不是 top-k 精准度。

## 1. 功能影响表（逐项）

符号：**新能力** = 以前做不到的事；**行为变化** = 同功能不同表现；**—** = 无功能影响。

| 项 | 类型 | 用户 / 模型可见的变化 | 回归风险 | 触达面 |
|---|---|---|---|---|
| **G-A1** `valid_from/valid_to` | **接收端（新能力的地基）** | 事实可以带"生效/失效时间"；默认检索**不加任何时间谓词**（今天怎么检还是怎么检） | 空值语义：`NULL`=未知，若不写死会出现"没给时间的事实永不失效"；若有人把它当过滤器 ⇒ 动候选集（违反红线） | 迁移 v10 + 契约 + wire + 写侧可选参数 |
| **G-A2** `superseded_by` + 渲染约定 | **新能力**（表达能力） | ① **active + `valid_to`**：结果里能出现"当时成立、现已不再成立"的事实，由**模型读标记自行判断**；② **archived + `superseded_by`**：只审计可见（`admin`），**不进 recall** | 与既有三套"不再当前"语义（archived / `supersedes_id` / trust 衰减）**叠加**，UI 与提示词必须定义优先级；"归档 + 标注"两条路径要不一致就会有脏状态 | `contradiction.ts` 裁决路径 + 提示词段 + `RecallHit` 两字段 |
| **G-A3** MinHash/LSH 实体归并 | **质量提升**（非新能力） | `related`/`probe`/`reason` 的实体清单更干净；矛盾检测的"共享实体数"更准 | **会动实体袋 ⇒ 动 entity leg 的 Jaccard ⇒ 动 41 条数字**；过度合并会把"两个人/两个项目"并成一个（伤召回）；**先 spike：真实库近重复比例若≈0 则不做** | `EntitiesDao.linkFact` + 死列 `entities.aliases` + 重扫 |

## 2. 三处能力增量的细节（这才是"功能影响"的主体）

### 2.1 时间有效性：从"只有当前"到"能表达并审计当时是否成立"

**能回答的新问题**（今天的 mem 一个都答不了）：

- "这条现在还算数吗" → 读 `superseded_by` / `valid_to`（**由模型判断，不是引擎过滤**）；
- "这是什么时候生效的" → `valid_from`；
- "这条为什么被取代 / 被谁取代" → `superseded_by` + `archive_reason`；
- （反向）"这篇文档/KB 产生了哪些事实" → G-A7 的溯源反查。

**必须先说清的两个功能边界**（否则会把它想成 graphiti 那样）：

1. **默认检索不做时间过滤**（graphiti 自己也不做 —— 见 `GRAPHITI_COMPARISON.md` §6.2：它的 `expired_at IS NULL`
   默认不生效，"现在是否成立"是**读者的判断**）。所以 mem 拿到的是**表达能力**，不是"自动只看当前"。
   谁想把它变成过滤器，就必须面对候选集变化 ⇒ 重冻（这是另一条改动，不是本项）。
2. **本提案的 `superseded_by` 主要写在 archived 行上**（`update` 与 `contradict_resolve` 都仍会归档）⇒
   这部分**只在 `admin`/审计里可见，不进 recall**。真正会出现在结果里的新形态是 **active + `valid_to`**
   （"曾经成立、现已失效、但没人取代它"）—— 这需要写侧（G-B1）给 `valid_to`，否则整层是空的。

**功能回归风险（最重要）**：mem 今天已经有**三套**"不再当前"的表达——`status='archived'`（检索看不到）、
`supersedes_id`（修订链）、trust 衰减（降权/闲置清理）。再加 `valid_to`（时间上不再成立）与 `superseded_by`
（被谁取代）就是**五套**。必须写死一张优先级表并进提示词，否则模型会在"这条 archived / 这条 superseded /
这条 trust 低"之间自行发明规则。**这是这批项里最容易做歪的地方。**

### 2.2 溯源：从"只记得内容"到"能回答为什么记得"

- **新能力**：`mem_admin detail` 能列出 `sources`；`mem_recall search` 能按 `source` 过滤（**只过滤、不参与打分**）；
  知识库侧新增反向查询"这篇文档产生了哪些事实"。**不加第 9 个工具**（守住 8 个）。
- **功能成立的前提是覆盖率**：`source_ref` 由调用方给，不给就是 NULL。所以功能上**它必须与 G-B1 同批或先行**，
  并且 `stats` 要如实报"有来源的事实占比"——否则就是下一个"字段存在、永远为空"的 `mirror_source`。
- **与知识库天然互补**：kb 的 managed `.md` 是"路径即真相"，`fact_sources(kind='kb_doc')` 正好把事实挂回那些路径。

### 2.3 写侧结构接收端：A 档建"收件箱"，B 档才送内容

- **依赖链**：`G-A1/A6/A7/A8`（列与读面） → `G-B1/B2/B4`（谁填） → 才可能有 `L1` 的"按主体取一组"。
- **功能上的硬事实**：A 档做完了，如果 B 档没做、调用方也不传，那么**所有新列都是 NULL**：
  功能增量为零，只会多出契约面与迁移成本。所以功能验收必须含 **"覆盖率"指标**（`stats` 报：
  结构化覆盖率、有来源占比、`assert_count>1` 的事实数、`valid_to` 非空数），而不是只看"字段上线了"。
- **G-B1 是唯一能把 L1 真正落地而不引入 LLM 的路径**（调用方模型手里已经有结构，只是没地方放）。

## 3. 两处质量提升（不是新能力）

| 项 | 功能价值 | 先验与前置 |
|---|---|---|
| **G-A3/A4 实体归并** | `related`/`probe`/`reason` 更准、矛盾检测的"共享实体数"更准、实体腿扇出可能下降 | **先验收益可能≈0**：mem 的实体是 jieba 名词，形态差异主要是全半角/空白，而 `normalizeWrite` 已覆盖；中文 2 字名的 3-gram shingle 会退化成空集 ⇒ 必须换字符 2-gram 且阈值要重标。**先做离线 spike（命中率），≈0 就不做** |
| **G-A6 断言计数** | 把"被独立说过几次"变成一个确定性计数；模型可据信封自己判断 | 必须写清"**计数≠置信度**"（客套重复也计数）；**不进打分**；若提示词不教用法，功能上等于没变 |

## 4. 发布面：哪些是用户可见行为变化

要进 `[0.6.0]`（0.5.0 已发布，`[Unreleased]` 必须为空）：

- **G-A6**：重复 `add` 不再是静默 no-op（返回新增字段）——最容易被用户感知的一条；
- **G-A8**：`entities.entity_type` 语义从"词性"改成"类型"（`admin detail` 显示会变）；
- **G-A2**：信封与提示词出现"已被取代/失效时间"的读法；
- **G-A7**：信封/`detail` 出现"来源"，`recall` 多一个可选过滤参数；
- **G-B1**：`mem_remember` 参数面显著变宽（契约 + MCP + CLI + client 四处派生）。

**模型可见但用户不可见**：`RecallHit` 的 `scores{final,…}`（G-A5，=在办 A6）。它**不改变功能**，只改变
模型能"看到什么"——所以它的价值在可解释性与后续验收，不在命中率。

## 5. 功能回归风险清单（按严重度）

1. **"不再当前"的语义叠加**（G-A1/A2 vs 既有 archived/`supersedes_id`/trust）：没有优先级表 ⇒ 模型自行发明规则。
2. **空字段**（A 档没有 B 档/调用方填）：功能"看起来有、实际全空"——`mirror_source` 先例。
3. **过度合并实体**（G-A3/A4）：把不同主体并成一个 ⇒ 伤召回，且会同时改两 store 的实体腿。
4. **误判传播**（G-B2）：写侧一句错的 `replaces` 让正确记忆静默失效 ⇒ 必须保留行 + `admin` 回滚 + `stats` 计数。
5. **顺序敏感**（G-B3）：簇重算每次不同 ⇒ 必须钉死遍历序（按 `entity_id` 升序），并做"两次重算逐字节一致"断言。
6. **类型变必填**（G-A8）：把可选项做成必填 ⇒ 零 LLM 写路径多一道门槛（graphiti 那边也是可选的）。

## 6. 性能（一句话）

本清单的运行期成本几乎全在**字段与读面**：G-A1/A2/A6/A7/A8/B1/B4 是列/表/契约，检索路径**≈0**；
唯一需要量的两处是 **G-A3/A4 的一次全库重扫与实体袋变化**（会动扇出，可能变快也可能变慢）与
**G-B3 的聚簇重算**（只读派生面，成本可水位线化）。细节与口径见 `IMPROVEMENT_FUNCTIONAL_PERFORMANCE_IMPACT.md`。

## 8. 一句话结论

graphiti 清单对 mem 的功能影响是**"扩展能力面 + 补审计与表达"**，不是"召回更准"：
**G-A1/A2/B2 让 mem 能表达'当时是否成立'，G-A7 让 mem 能回答'为什么记得'，G-A1/A6/A7/A8+B1 让写侧结构有地方可落**；
而精准度那一层它给不了（能给的路径 N1–N3 都被排除）。落地时必须守住两件事：
**"不再当前"必须只有一张优先级表**，**新列必须有覆盖率指标而不是成为下一个空字段**。
