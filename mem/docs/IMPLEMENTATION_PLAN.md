## 1. 批次 0

### P-02 回归网

- **做什么**：给评测加 `nDCG@k`、top-3 相关条数两个指标；新增查询派生引擎；新增夜间真模型评测作业。
- **怎么做**：派生引擎为确定性实现（不调模型）：从既有事实反推"它能回答的问题"，生成 `must_include` / `must_exclude` 与两类守卫（无时间词守卫、无关守卫），并满足碰撞敏感行为的**三条**要求——① 与真实库同量级的长度分布；② **主动植入含关键碎片字面串的无关条目**；③ **反事实臂**：移除该碎片后 gold 应回到首位，作为 fixture 自检。另强制两条：**查询不得包含 gold 的唯一字面**、每条查询输出它与非 gold 事实的片段碰撞率。**两个新指标放进 `report` 的兄弟字段**（`report.ranking`），**不进 `report.summary`**——`summary` 的 7 个键被 `toEqual` 精确断言，多一个键就会红。派生数据默认写临时目录、不进仓库。PR 只跑确定性 stub 版本，夜间跑真模型版本。
- **影响**：不改运行期行为；新增评测资产与一个 CI 作业。
- **收益**：任何检索改动都有可判定的验收（含守卫不误伤、碰撞率可见、反事实可证）；41 条既有精确断言保持不变。

### P-03 写侧密钥/PII 守卫

- **做什么**：在 `mem_remember` 写入入口加高置信形状检查，命中即拒绝并给出可操作提示。
- **怎么做**：只识别高置信形状（provider key 前缀、PEM 块、带凭据的连接串、Luhn 校验卡号、身份证格式）；命中时**拒绝该条**并提示改为记录"存放位置/获取方式"（或按配置改为警告 + 显式覆盖）；**只对事实生效**，`kb_add` 与知识库文档不动；不做静默改写；不回溯扫描。
- **影响**：写路径多一次纯函数检查（微秒级）；错误面走既有工具错误口径，不加字段。
- **收益**：明文密钥/PII 不再进入持久库与远端备份历史。验收口径：各类 key/PEM/连接串**正例必中**；反例集零误伤，**反例集必须包含本仓自己的 `.env.example` / README 里的合法示例 token** 与文档占位符。

### P-04 提示词与纠错口径

- **做什么**：内置提示词增加三段行为口径。
- **怎么做**：① 记忆是过去的记录、不是当下指令，与当前任务无关时可完全忽略；② 核实到过时/错误用 `update` 纠正并附核实依据；③ 不要把 `recall` 返回内容原样回记。**内置正文只是 `fallback`、文件优先**（`prompt.ts` 的既有语义：文件缺失或空白时才用内置）⇒ 另需一个交付动作：`[0.6.0]` 的**升级说明里给出这三段可粘贴的文案原文**，让已自定义 `mem-memory-usage.md` 的用户自己加进去。
- **影响**：纯文案，运行期零成本；提示词长度小幅增长。
- **收益**：**对未自定义** `mem-memory-usage.md` 的用户生效——降低误用与自我强化回环、纠错有明确通道；自定义用户按升级说明手动补齐后同等生效。

### P-05a 停止发出假溯源

- **做什么**：不再让事实视图携带常量溯源字段。
- **怎么做**：当前 `mirror_source` 在唯一写入点被写死为常量 `'user'`、`mirror_target` 从无写入点，而两者未被保留诊断字段过滤；处理为①停止写入该常量、②从模型面视图与面板移除、③列按"弃用"标注留待后续迁移清理（本次不删列）。两列均为可空 `TEXT`，停写不破坏写入路径。
- **影响**：事实视图与 `admin` 载荷各少两个字段。删除出参不需要 wire bump——已确认 client / CLI / MCP 三处都不读这两个字段。
- **收益**：模型不再收到一个假的来源常量（修复长期存在的错误信息）。

### P-05b 落库抽取器已算出的实体属性

- **做什么**：把抽取器已经算出、但被丢弃的实体 `type` / `method` 写进库。
- **怎么做**：抽取器返回 `{name, type, method}`（`type` 是分词器词性、`method` 是 `'jieba'`/`'regex'`），六个调用点目前只取 `name`、`entities` 表只写 `name`；改为传递完整对象并在写入时带上 `entity_type` / `extraction_method`。**不做版本号重扫**：升 `ENTITY_EXTRACTOR_VERSION` 会全库重跑三元组抽取、**覆写 HRR 向量**、并把矛盾检测重新排队（`contradiction_log` 可能新增条目）；而这两列**今天没有任何消费者**（core / contract / plugin 三处均不读）⇒ 接受**新旧混合**（新实体有真值、旧实体留默认）。若将来要为旧行补齐，用**按名的定向 UPDATE**（列在 `entities` 表上、按名而非按链接），不碰三元组 / HRR / 矛盾队列。
- **影响**：写入侧多两列赋值；**无重扫、无 HRR 覆写、无矛盾重排**；检索结果不变。
- **收益**：`entity_type` / `extraction_method` 从此对**新写入**有真值（现状是"算出即丢弃"），类型字段可用于统计与呈现。

### P-06 数据根备份纪律

- **做什么**：明确数据根的版本化纪律，并加一条可离线检测的 WAL 健康提示。
- **怎么做**：文档写明不版本化 `memory.db-wal` / `-shm`、提交前执行 `wal_checkpoint(TRUNCATE)`；`admin stats` 只增加 **WAL 文件大小/存在性** 的告警字段（一次 `statSync`）。**"瞬态文件是否被 git 跟踪"只写进文档**，不在 stats 路径里引入 git 调用或子进程（保持零运行期依赖与离线可用）。
- **影响**：文档 + 一个统计字段 + 一次文件状态读取。
- **收益**：能就地发现 WAL 异常；避免 db/WAL 混搭导致的恢复风险。

## 2. 批次 1（一次 schema v10 迁移）

### P-01 逐臂证据信封

- **做什么**：让结果能回答"这条靠哪条腿、原始分多少"。
- **怎么做**：融合阶段除融合分外同时返回每个候选在各腿的原始分与归一值（该腿未召回为 null）；`RecallHit` 增加可选 `scores` 与 `final`；工具面增入参 `include_scores`，**默认 false**；**面板的查询页**与评测脚本显式打开。
- **影响**：入参需在 `remote.ts` 的 recall codec 里声明（面板会发它）；**不 bump**（可选字段，见 §0 判据）；默认关时零 token 增量。**`fuse` 是 memory 与 knowledge 共用的内核**（唯一调用点是 store-agnostic 的混合检索），所以本项**同时波及知识库，而知识库没有冻结评测网** ⇒ 验收必须附一张一次性知识库对照（≥10 条 `kb_query` 的前后 id / 顺序 / 分数）。
- **收益**：模型与面板可见排序依据；后续任何排序类改动都能先回答"这条靠哪条腿进来的"。

### P-07 事实有效期与取代标注

- **做什么**：让"这条何时成立、何时被谁取代"可写可查，且不改变检索候选与排序。
- **怎么做**：schema v10 增两列 `valid_from` / `valid_to`（可空，`NULL` 表示未知、不参与任何语义）；写入路径为：**`valid_from` 由 P-13 的 `event_date` 写入**、**`valid_to` 由 P-13 的 `valid_until` 写入（行留在 active）**，另有两条审计路径也写 `valid_to`（`update` 修订链与矛盾裁决"真阳性"给败方，这两条同时归档该行）；读路径为 `admin detail` 与面板展示有效期与"被谁取代"（**从既有 `supersedes_id` 反向派生，不新增冗余列**）；检索默认不加时间谓词。信封里的 `valid_to` **仅在非空时序列化**（照 `RecallHit.truncated?` 的先例）——**可达性由 P-13 的 `valid_until` 保证**（否则两条写入路径都归档该行，而所有腿只取 `status='active'`，该字段永远序列化不到）。
- **影响**：迁移新增两列（可空、无默认）；默认检索 id/顺序/分数逐字节不变。
- **收益**：有效期与取代关系可审计；事件时间成为可见的决策依据而非隐藏状态。

### P-08 事实来源与反向溯源

- **做什么**：记录每条事实的来源，并支持反向查询。
- **怎么做**：新表 `fact_sources(fact_id, kind, ref)`，`kind ∈ {session, kb_doc, tool, manual}`，`ref` 建索引；`mem_remember` 增可选 `source_ref`（未给为 NULL，不臆造）；读面为 `admin detail` 列出 sources、`recall` 增可选 `source=` **只过滤**、反查"某来源产生了哪些事实"走 **`admin list` 增 `source=` 过滤**（`detail` 是按 `fact_id` 取单条，枚举类是 `list`；两处 `source=` 语义一致）；`admin stats` 从第一天起报来源覆盖率。**过滤层级必须照 `category` 的先例做腿内谓词**（代价是 4 条腿各一次子查询、自指增广时 ×2），**且必须用 `EXISTS` 而非 `JOIN`**——一条事实有多个来源时 JOIN 会行扇出，而各腿是 `ORDER BY bm25 LIMIT cap`，重复行会吃掉 `cap` 名额、变相降低召回。**不放在融合之后**（融合后削候选会返回不足 `limit`，并让空集被放宽档重试误当作"门槛太严"而白跑一遍）。写入说明：**放宽档重试不受 `source=` 影响**。
- **影响**：一次迁移（新表 + 索引）；未给 `source_ref` 时行为逐字节不变。
- **收益**：能回答"为什么记得"，并能反查某来源产生了哪些事实（含知识库文档）；覆盖率指标防止字段变空。

### P-13 事件时间写入（可选 `event_date`）

- **做什么**：让调用方在写入时给出"这件事何时发生 / 有效到何时"，为 P-07 的 `valid_from` / `valid_to` 与 P-11 的时间窗腿提供来源。
- **怎么做**：`mem_remember` 增**两个可选参数** `event_date` 与 `valid_until`（ISO 日期/时间，未给为 NULL）；前者写 `valid_from`，后者写 `valid_to` **且不归档该行**（这样"仍然有效但已知截止于某时"的事实能留在 active 集合里、随 recall 返回）；不参与检索打分，只被时间窗腿、展示与信封读取；`valid_from` **覆盖率**从第一天起进 `admin stats`。
- **影响**：两个入参需在 `remote.ts` 的 remember codec 里声明；**不 bump**（可选字段，见 §0 判据）；未给时行为逐字节不变。成本为**上界 ≤ +154 token**（那是最小集两参的简写档口径，本项两个参数与之同量级）；校验开销微秒级。
- **收益**：事件时间第一次进入库；它同时救活 P-07 的 `valid_from`（否则该列无写入者）与 P-11（否则窗口腿只能读写入时间）。

### P-10 重复断言计数（可选）

- **做什么**：逐字重复的写入不再静默，而是累计计数。
- **怎么做**：`facts` 增 `assert_count`，**新行默认 1**（语义 = "被断言过的次数"），纯重复写入 +1 并在返回里给出计数；**归档事实被 revive 不计入**（revive 走 `changes === 0` 分支的复活路径，与"又被断言一次"是两件事）；`admin detail` 展示；不进打分。
- **影响**：一列 + wire 字段；读者为 `add` 的返回与 `admin detail`。
- **收益**："这条被独立说过几次"成为可观察信号且读数无歧义。

## 3. 批次 2

### P-11 中文时间戳查询（默认关闭）

- **做什么**：支持按中文时间表达检索。
- **怎么做**：新增确定性中文时间解析（相对期：今天/昨天/前天/本周/上周/这个月/上个月/今年/去年/最近 N 天；绝对期：`yyyy年m月d日`、`yyyy-m-d`、`yyyy年m月`、`m月d日`），不引第三方依赖；新增**时间窗腿**参与融合，**只作一腿、不作过滤器**；该腿**只读事件时间 `valid_from`**——**没有事件时间的事实不作为该腿的候选**（其它腿照常返回它），**不回退到写入时间**；该腿必须在自指增广的两遍里都存在（编排按腿下标合并）；权重沿用既有三键契约（共享 jaccard 权重位）；配置项**默认关闭**。
- **前置**：**P-13 必须先落地**（否则窗口腿只能读写入时间，"上个月做了什么"不可回答）；**P-02 的回归网必须先落地**（"多一条腿是否值得"只能由它在融合层判定）；`valid_from` 覆盖率从第一天起进 `admin stats`，作为"这条腿值不值得打开"的判据。
- **影响**：默认关 ⇒ 对现有查询零影响；打开后初期只对带事件时间的事实生效。
- **收益**：能回答"上个月做了什么"这类问题；硬过滤形态不采用（会丢 gold）。

## 4. 验收与门禁

| 门禁 | 何时 | 覆盖 |
|---|---|---|
| **快档** | 每个批次收口 | 该树 build + typecheck + 全套测试 + `guard` + 四个自测 + `prepublish:assert` |
| **发版档** | 涉 base/接口/发布面，以及批次 1 | 三包严格门禁（含 pack 与 dsh 下限门）+ 两棵树 mount smoke + root `gate` / `release:check` |
| **迁移** | 批次 1 | 每个起始版本升到与全新 schema 一致；单向迁移须在升级说明里写明备份前提 |
| **wire** | 批次 1 | 判据见 §0：新增可选字段必须声明进 codec（`remote_wire.spec.ts` 的 `declared ⊇ contract`），**不 bump**；删载荷字段前核对 client / CLI / MCP 三个消费面 |
| **默认路径** | 全批次 | 未启用新功能的默认调用 **id/顺序/分数逐字节不变**；**凡声称"冻结集不变"的项必须附实跑对照**（`report.summary` 七个数字 + id/分数） |
| **共用内核** | P-01 | `fuse` 同时服务 memory 与 knowledge ⇒ 附一次性知识库对照（≥10 条） |
| **不变量** | P-07 / P-08 | 不变量可由一条 SQL 校验，且**植入违规必须失败**；覆盖率指标可读 |
