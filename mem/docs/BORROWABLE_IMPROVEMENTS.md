## 0. 一页结论

- **可借鉴项去重后 24 条**：H 独有 12、G 独有 12、两者同一机制 6（重复计一次）。**四轮测量共 24 块**
  （8 + 8 + 1 + 7）。**状态列已按 `BORROWABLE_IMPROVEMENTS_REVIEW.md` 返工**（该复核的 11 条逐条我独立核过，
  全部成立）：**真测量判对的**是 A5 / A7 / L2 / L3；**F4 的 raw 结论是附条件采纳**（本表维持"不采纳"是**判断**不是测量）；
  **A3、A4 的 null 来自语料/人群构造上无可测效应**（A4 的受测人群由构造保证为 0）⇒ 改 ⬜ 未测 / ⚠️ 条件否决；
  **A8 是取舍裁决**（其 `gold_kept` 只数 id，看不见胜出臂 21/86 条正文为空，且 `frozen_30` 的 verdict 是 adopt）。
  **B1 在本语料不采纳**（真实库实体名 100% 逐字在正文里、替换式供给净负、四次跨进程标注 48.44% 分歧），
  且**即使复活也有代码阻塞**（`reindexEntities` 会把调用方供给的实体静默清掉）。
  **A2 能力缺口为真、但强数字近循环**（R2-2 的 gold 就是那条腿的谓词）⇒ 条件**未**解除，发布前置 = 真实时间查询集。
  结构性接收端（G-A1/A2/A6/A8）测出**默认逐字节不变、迁移 2 ms、不变量可验**，但**没有读者就是死列**
  （见 §2.1/§2.2/§2.3 的加注）；**G-A7 只能生产期测**。
- **跨卡不可比（复核 §4）**：本表引用的"冻结 41"数字来自**四个不同网络** —— `frozen-real`（F4/R1，real embedder，
  `must_exclude 27/41`）、`frozen-stub`（L2/R1 复现生产断言，`29/41`）、`snapshot-85×20`（真实库快照）、
  `synthetic-78`（R3，完全不碰真库）。**不在同一网络上的读数不可横向比较。**
- **功能价值最高的三处**（都与"精度"无关，是**能力面**）：
  1. **时间有效性**——`valid_from/valid_to` + `superseded_by` + 写侧 `replaces`（H A1/A2 + G-A1/A2/B2）；
  2. **写侧结构接收端**——让调用方模型把 subject/attribute/entities/event_date/source 直接写进来
     （H B1 = G-B1，是"按主体取一组"的唯一零 LLM 路线）；
  3. **溯源**——`fact_sources` + 反向查询"这篇文档产生了哪些事实"（G-A7，H 无对应物）。
- **一条主线（两份对照独立指向同一处）**：**先建"接收端"（列 / 信封 / 读面），再由写侧送内容**。
  没有写侧内容，A 档的新列全是 NULL——功能增量为零，只剩迁移成本（mem 已有 `mirror_source` 这个先例）。
- **一条边界**：两位对手的"准"都来自**写侧 LLM 抽取 + 重排**，mem 刻意都不做 ⇒ 能借的是**机制与设计约束**，
  不是精度。**测量已经证明**：本仓最像"精度修复"的两项（FTS 分数函数、预算装箱）分别被否决/更差，
  "融合后门槛弃答"被证明**没有可用尺度**。

## 7. 一句话

从两个系统能借来改进 mem **功能**的，是**能力面与纪律**：**时间有效性（H A1/A2 + G-A1/A2/B2）、
写侧结构接收端（H B1 = G-B1）、溯源（G-A7）、派生态（H B2/B3 = G-B3）**，外加**写侧密钥守卫（H A1）**
与**注入框架文案（H A11）**；而它们的"精度"（RRF/MMR/CE/写侧 LLM 抽取）已被明确排除，
本仓两次"精度式"候选（F4、A8）也已被自己的测量否决。**先建接收端与证据信封（A6/E0），
再由写侧送内容**——这是两套系统独立指向的同一条路。
