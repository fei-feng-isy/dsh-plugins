## 0. 为什么只剩这一张卡

`BORROWABLE_IMPROVEMENTS.md` §6：两轮 16 卡之后，**质量/精度方向的候选全部被否决**；唯一未测的是
**B1/G-B1 的原始提案——由调用方（agent）在写入时把结构给出来**。R2-6 只测了**规则**供应商（已否决：
精度代理 1/82）。本卡测**调用方供应商**：它能拿到多少、对合规率与方差有多敏感、要付多少 schema 税。

## 1. 红线（本卡特有，先看）

- **不要读、不要打印用户真实记忆的正文**。本卡**只用脚本构造的真实形状 fixture**，其"真值"由构造时写下。
- 真实库只用于**复用 R2-6 已有数字**做基线对照（不新增正文读取）；若要复用第一轮的真实库快照，
  仅允许读 **id / 长度 / 分数 / 表结构**，不得读 text。
- 其余沿用既有纪律：不改生产代码；identity 断言；臂间同候选集；每卡 JSON（含 `loadpath`/`identity`/复现命令）；
  无 `text`/`content` 类长字符串。

## 2. S1 · fixture 与"真值"（前置）

构造一个**真实形状**的记忆库（40–80 条，长度分布复刻真实：中位 ~300、含 9 字符短事实与 800+ 长笔记），必须含：

1. **实体型查询有 gold**：每个主题有 2–4 条事实共享一个规范实体；同一实体在正文里出现**别名/全半角/大小写变体**
   （用来测"调用方给规范名"的增益）；
2. **自指族**：一条身份事实（第三人称"用户…"）+ 至少一条**含字面碎片**的无关长笔记（`用户是` 类，作为碰撞载体）
   + 一条"只提到用户但主体不是用户"的政策事实；
3. **时间**：若干事实带可识别事件时间（用于窗口腿）；
4. **一条反事实断言**（删掉碰撞碎片 → 结果应回正），证明 fixture 不是健康合成语料。

**真值表**（构造时写下，供"完美调用方"臂使用）：每条事实的规范实体集、subject、attribute、event_date。
写进 fixture JSON（不含任何真实数据）。

## 3. S2 · 供应商臂（同一 fixture，只换"结构化字段从哪来"）

| 臂 | 结构来源 | 说明 |
|---|---|---|
| **A0 基线** | 无 | 现状：jieba 实体 + 启发式三元组 |
| **A1 规则** | 生产规则抽取 | 与 A0 同源；主要用来在**同一 fixture** 上给出对照（真实库的数字引 R2-6） |
| **A2 完美调用方** | fixture 真值 | 规范实体集 + subject/attribute + event_date（**能力上限**） |
| **A3 部分调用方** | 真值按比例丢弃 | 合规率 100/50/25/0%（字段整组丢弃，seed 固定） |
| **A4 有噪调用方** | 真值扰动 | 别名/大小写/全半角变体注入 10% / 30%（模拟"调用方给的名字不一致"） |
| **A5 合并** | 规则 + 调用方 | 两者都写，冲突时保留两者（各自带来源标记） |

**指标**（每臂）：
- 实体型查询：top-1 / top-3 相关数、实体袋中位宽、候选扇出（`activeFactsForAllEntities` 的行数）；
- 自指族：身份问题 top-3 相关数、含字面碎片的长笔记**名次**、以及**并集是否收窄**（组作额外一腿 vs 组内过滤两形态分别测）；
- 时间：带 `event_date` 的窗口查询 `missing / in_top3`（复用 R2-2 的口径）；
- 排序不变性：A0 与"打开字段但全为空"两个 pass 的 id/顺序/分数必须**逐字节相同**。

**裁决规则（预注册，写在报告开头）**：
- **采纳**：A2 相对 A0 在**至少一类查询**上有实质提升（top-1 或 top-3 相关数上升，且无 gold 丢失），
  且 A3 在 **50% 合规**下仍保留 ≥50% 的增益，且并集不收窄；
- **带条件采纳**：只有 A2（完美）有效而 A3/A4 迅速衰减 ⇒ 结论是"上限可行、依赖合规与一致性"，
  并给出"生产期必须 instrument 合规率与一致性"的指标；
- **不采纳**：A2 在质量指标上零位移 ⇒ 连完美调用方也救不了（那 B1 就该整体放弃）。

## 4. S3 · 方差与一致性（本卡的核心风险）

- 对同一批事实做**两次独立"标注"**（用两套确定性扰动规则模拟两个不同的 agent/会话）：
  比较两次的 (实体集合、subject、attribute) 差异率，以及**同一查询的返回 id/顺序位移**。
- 报：字段级差异率、位移查询数、top-1/top-3 变化的查询数。
- **结论必须回答**：调用方供给的方差会不会让"同一份记忆"在两次写入后表现不同（这是 mem 冻结评测与真实库一致性的风险源）。

## 5. S4 · schema 税与默认不变（决定契约形状）

- 设计 2–3 个候选契约形态并量**字符/token**：
  ① 每个字段一个可选参数（`subject/attribute/entities/event_date/source_ref/replaces/...`）；
  ② 单个 `structure` JSON 对象参数；③ 只加最小集（`entities` + `event_date`）而其余留在 `update`。
- 量：`mem_remember` input schema 的**增量字符数**（当前约 5.0k 字符作基线）、估算 token、以及单次写入的
  校验/落库耗时增量；说明"工具定义是否每轮都在上下文里"取决于宿主，给出两种口径。
- 断言默认不变：未给任何新字段时，写入路径与检索结果的**逐字节不变**（用生产臂 identity + 前后对比证明）。
