# 派单简要：不确定改进项的**先测后改**测量战役

> 本文是派单用简要，不是交付物。执行者按本文做完后，交付物只有：
> `mem/docs/spikes/IMPROVEMENT_SPIKE_RESULTS.md` + `mem/scripts/spikes/` 下的脚本 + `mem/docs/spikes/raw/*.json`。
> **绝对不许改 `mem/packages/**`（生产代码）、不许改默认配置、不许动 CHANGELOG/版本。**
> 机制原型一律活在**脚本里**（照抄 `mem/scripts/bench-rerank-ab.mjs` 的 R2"假设修复"臂的做法）。

## 0. 目标

对下面列出的**"可能有效但未证"的改进项**，先用**可复现的离线 A/B** 测出结论，
每条产出一个**裁决**：**采纳 / 不采纳 / 不适用（并说明为什么）**。
判据是数字与既有纪律，不是直觉。**测完之前不许实现。**

## 1. 测量网（三个口径，缺一不可）

1. **冻结集**：`mem/packages/core/test/fixtures/eval_zh_relations.jsonl`（41 条，7 项精确断言）。
   用现有驱动方式（参考 `mem/scripts/bench-floors.mjs`）；若某臂需要语义 live，用真模型跑。
2. **真实库快照**（主网，因为冻结集看不见真实病理）：
   `~/.avantf/memory/memory.db` **只读 + `VACUUM INTO` 到临时目录**；运行时 `dataHome` 指向临时目录；
   **一个字节都不许碰 `~/.avantf/`**。查询集用 `mem/docs/RERANK_AB_REAL.md` §1 的两组
   （真实库 14 条 + 门槛 20 条）并沿用其中的 gold 定义；**不打印任何真实正文**（只打 id/长度/分数）。
3. **真实形状 fixture**（需要时）：长度分布复刻真实（中位 ~313 字符、含 9 字符短事实与 800+ 字符长笔记）、
   必须含"正文恰好含改写查询字面碎片"的干扰项与一条**反事实断言**（`mem/docs/SELF_QUERY_RELEVANCE.md` §6.2 同款）。

**共同纪律**（缺一条该臂作废）：
- **生产臂 identity 断言**：脚本必须断言"基线臂复现产品实际返回的顺序"（同候选集、同门槛、同 limit）。
- **臂间同候选集**：只允许改被考察的那一层（分数函数 / 融合规则 / 候选合法性），其余逐字相同。
- 每条臂都输出 JSON（原始数字）+ 可复现命令；报告里的每个数字都要能指回 JSON。

## 2. 测试卡（按成本从低到高；P0 全做完再动 P1，P1 有结论再动 P2）

### P0-1 F4：FTS 腿分数函数（bm25 → 覆盖率 / 混合）
- **假设**：bm25 在 OR 起来的三元组上奖励"偶然含多个查询碎片的长笔记"（2026-10-04 事故形态）。
- **臂**：A=生产 bm25；B=覆盖率 `countMatchedTerms/terms.length`；C=混合（归一 bm25 × 覆盖率）。
- **指标**：41 条（`must_include/must_exclude/top-3 相关数`）；真实库 20 条（top-1/top-3 相关数）；
  `我是谁？` 系列干扰项（#103/#117/#125）的排名位置。
- **裁决**：`must_include` 不降 **且**（`must_exclude` 或 top-3 相关数**严格上升**）**且**非自指查询候选并集不收窄 ⇒ 采纳。

### P0-2 L2：≥2 条腿准入（**负假设，预期不采纳**）
- **臂**：在生产融合池上施加"≥2 腿 有证据 或 与 top-1 差距 ≤ δ"（δ ∈ {20%, 40%}）。
- **指标**：被删掉的 gold 数、top-3 相关数、事故 fixture（单腿强命中）是否退化。
- **裁决**：有任一 gold 被删 或 top-3 不升 ⇒ **不采纳**（记录数字，作为"该规则反证"的存档）。

### P0-3 A5：乘性 boost（recency / trust / proof）
- **臂**：生产序；`final × (1+α(signal−0.5))`，α ∈ {0.1, 0.2}；signal 分别取 recency（按 `updated_at`/`created_at`）、
  trust（`trust_score`）、proof（占位=1，mem 无 proof 时跳过该项）。
- **指标**：同 P0-1。
- **裁决**：严格上升且 `must_include` 不降 ⇒ 采纳；否则不采纳。

### P0-4 A8：预算装箱（跳过超预算继续 vs 截断）
- **臂**：生产截断；"整条装箱、放不下的跳过、实在放不下整条返回 top-1"。
- **指标**：返回条数、文本完整性（`truncated` 命中数）、`empty_rate`/`must_include`、输出 token。
- **裁决**：`must_include` 不降 且"半截文本"归零 ⇒ 采纳。

### P1-1 A3：实体规范化（trigram 合并 + 共现）
- **臂**：离线对全库实体做 trigram Jaccard 合并（阈值 ∈ {0.5, 0.7, 0.9}）+ mention_count/共现；
  重算实体腿候选与分数。
- **指标**：实体型查询（真实库 5 条 2 字 + 10 条实体型）top-1/top-3；实体袋中位宽与扇出；
  **合并对数 + 抽样审计**（人工看 20 对，统计过度合并）。
- **裁决**：实体查询提升 且 抽样过度合并率 < 5% ⇒ 采纳；否则不采纳。

### P1-2 A2：中文时间窗
- **臂**：自研时间窗解析（先做相对期 + 绝对期）+ 窗口腿（有索引的 SQL）；对照无时间语义的基线。
- **指标**：15 条中文时间查询（含相对/绝对）中窗口内 gold 的 rank；**5 条无时间守卫查询**是否被误伤；
  解析误判逐条人工审计（对照 hindsight 的 dateparser 误判教训）。
- **裁决**：窗口 gold rank 显著改善 且 守卫误伤 = 0 ⇒ 采纳。

### P1-3 A7/F2 可行性判定（可能结论是"不适用"）
- **问题**：mem 是否存在**跨查询绝对可比**的融合后分数？没有的话，"融合后门槛弃答"就是不适用。
- **做法**：多查询分数分位数对比 + 代码核对（`store/floors.ts` 的设计说明）。
- **裁决**：无绝对尺度 ⇒ **不适用**，弃答继续钉"每腿绝对原始分"（现有机制），并写明原因。

### P2-1 L1/B1：主体/属性 spike（需要判定 + 采样审计）
- **臂**：规则式抽取 subject/attribute（不调 LLM）+ 查询侧主体判定；对照基线。
- **指标**：自指 6 哨兵；碰撞载体反事实（删掉 `用户是` 碎片 → 结果应回正）；
  `subject=用户` 组是否包含 #103/#125 且是否漏掉 #4；抽取精度抽样（20 条）。
- **裁决**：**无法在排除命名的干扰项的同时不伤 gold ⇒ 不采纳**（这是预期结果，要用数字证明）。

### P2-2 L3 pilot：长事实分块（真模型，成本最高）
- **臂**：对 `N>512` 的事实分块（K ≤ 3），聚合规则先定两种：max-over-K 与 "不许超过整事实自身的分"。
- **指标**：目标查询 top-3；长笔记的排名位置（不许变差）；向量数 / RSS / 启动增量；写入延迟倍数。
- **裁决**：top-3 上升 **且** 长文位置不变差 ⇒ 采纳；否则不采纳。（若成本不可控，只做 pilot 并**明确标注未完成**。）

### P2-3 A4：索引文本并入实体名/日期
- **臂**：临时库加真实列 + 第二张 external-content FTS 表 + 触发器。
- **指标**：索引字节、p50 变化、"只有实体名命中"的查询是否改善。
- **裁决**：实体名查询改善 且 索引 < 2× 且 p50 < +20% ⇒ 采纳。

### P2-4 A6：信封逐臂分（只量成本，不需要 A/B）
- **指标**：每 hit 增加的字节/token、序列化耗时、`admin.stats`/面板载荷变化。
- **说明**：它对检索质量**无影响**，只需给出成本数字供排期。

## 3. 交付物

- `mem/docs/spikes/IMPROVEMENT_SPIKE_RESULTS.md`：**开头一张总表**（项 / 裁决 / 关键数字 / 脚本路径），
  之后每项一节（假设、臂设计、口径与规模、数字、裁决与理由、复现命令）。
- `mem/scripts/spikes/bench-*.mjs`：一臂一脚本或一脚本多臂，含 identity 断言。
- `mem/docs/spikes/raw/*.json`：原始输出。

## 4. 验收

1. **P0 四项全部有裁决**；P1/P2 按顺序推进，未完成的必须写明"未测 + 原因"。
2. 每项至少两条臂，**生产臂 identity 断言通过**（断言本身写进 JSON 与报告）。
3. ≥3 项给出**不采纳**的实测依据（L2/L4①/P2-1 是预期候选）。
4. `git status` 只出现 `mem/docs/spikes/**` 与 `mem/scripts/spikes/**` 新增；
   `mem/packages/**`、配置默认值、CHANGELOG、版本号**零改动**。
5. 报告里每个数字都能指回 `raw/*.json`；不给无法复现的数字。
6. 真实库全程只读（`VACUUM INTO` 快照），**不打印正文**。

## 5. 明确不做

不实现任何机制到 `packages/**`；不改默认配置；不跑全量门禁（那是落地后的事）；不下载新模型；
不把"看起来更好"写成结论——**没有数字就是未测**。
