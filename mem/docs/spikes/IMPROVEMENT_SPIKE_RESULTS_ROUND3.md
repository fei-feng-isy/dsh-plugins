gold 拉进候选。**合规率衰减是「每条事实是否供给」的函数，名字噪声只有在一组事实全被写歪时才咬人**——

| 还原正文（重建 FTS） | `[28,30,31,29]` | 是 | 1/2（**与基线逐条相同**） |

⇒ **反事实非空**：这个 fixture 不是「健康合成语料」，它真的带着 2026-10-04 那类字面碰撞病；而删掉碰撞碎片
确实让结果回正。这也说明：**A0 上自指族的 1/2 损失是载体造成的**，规则组（groupleg）与调用方供给都能修它，
**但两者修的是同一件事，后者没有额外价值**。

### 3.6 四条逐字节断言（全部通过，见 raw JSON 的 `assertions`）

| 断言 | 结果 |
|---|---|
| fixture 自检（alias 无规范字面 / literal 有 / 载体有 `用户是谁` / 身份条无 `用户是` / 正文互不相同） | **34/34** |
| 生产臂 identity（脚本 pass ≡ `rt.recall`） | **17/17** |
| **A0 vs「打开字段但全空」**：脚本 id+分数、产品 id+分数**双双逐字节相同** | **17/17** |
| **A1 ≡ A0**（全部 32 行：id + 池宽） | **32/32** |
| **A3@0% ≡ A0** | **17/17** |
| 守卫（3 条无时间词查询 × 9 臂：窗口腿开/关）逐字节相同、解析为时间的 0 条 | **27/27** |

### 3.7 裁决

**有条件采纳（带条件采纳）**。判据逐条：

- **实质提升**：成立（alias 形状 top-3 gold `0/18 → 15/18`，top1 `0/6 → 3/6`；时间窗 top-3 `1/3 → 3/3`）；
- **无 gold 丢失**：成立（alias `gold_in_pool 0/18 → 18/18`；literal 6/6 不动）；
- **并集不收窄**：**条件成立**——groupleg 保并集（A2 plain 池 2.33 = A2 groupleg 池 2.33），
  **filter 收窄**（→2）⇒ 若采纳分组能力，只能采纳 groupleg 形态；
- **50% 合规保留 ≥50% 增益**：**不成立**（alias top-3 保留 **40%**、top1 保留 33%）。**时间族保留 100%**
  （n=3，3 条 gold 日期恰好都被抽中），已按预注册读法记为 `alternative_reading_passes=true`，但不据此升级裁决。

⇒ **结论：上限很高，但它取决于合规；当前没有任何证据表明真实调用方的合规率足够。**
并且上限本身**只对 alias 形状成立**：在真实库更常见的 literal 形状（R2-8：实体名 100% 已是正文子串）上，
A2 **零位移**。**B1 若上线，收益预期必须写成「取决于规范名缺失率 × 结构化覆盖率」，而不是 A2 的数字。**

## 4. S3 · 方差与一致性（本卡的核心风险轴）

两次独立标注（两套确定性规则，模拟两个会话）：**A = 构造时的规范真值**；
**B = 同一批事实、第二个会话的写法**（50% 的事实照抄正文里看到的形式而不是归一化的规范名、15% 少写一个实体、

| 实体集合 | **24.36%**（19/78） | **17.95%**（14/78） |
| subject | 15.38%（12/78） | **3.85%**（3/78） |
| attribute | 10.26%（8/78） | **0%**（8/8 都是措辞差异） |
| event_date（10 条有日期） | **30%**（3/10） | 0%（都在 ±1 天内，但**已经跨出单日窗口**） |
| **至少一个字段不同** | **43.59%** | **19.23%** |

**查询级位移（14 条：8 实体 + 3 自指 + 3 时间）**

| 类别 | id 完全相同 | top-1 改变 | top-3 集合改变 | 平均位移位数 | 平均集合 Jaccard |
|---|---|---|---|---|---|
| 全部 | **7/14** | 1/14 | **6/14** | 1.36 | — |

**结论（直接回答 brief 的问题）**：**会。**同一批记忆被两个会话各写一次之后，**14 条查询里有 7 条返回

## 5. S4 · schema 税与默认不变

### 5.1 基线（口径先说清）

`toolInputJsonSchema(TOOL_SPECS[mem_remember])`（**MCP 面用的生产推导函数**，不是手抄）：

### 5.2 三种候选契约形态的增量

候选 = **同一个 `RememberUnion` 分支 `.extend()` 上新字段**，再走**同一个**生产推导函数 → 增量是纯增量。
两档描述：**详述**（生产风格的 40–60 字中文说明）/ **简写**（「主体；可选。」）。

| 形态 | 描述档 | Δ字符（紧凑） | Δtoken | Δ字符（美化） |
|---|---|---|---|---|
| **① 每字段一参**（subject/attribute/entities/event_date/source_ref/replaces） | 详述 | **+1638** | **+893** | +2415 |
| ① | 简写 | +1095 | +383 | +1872 |
| **② 单个 `structure` JSON** | 详述 | **+1161** | +407 | +2172 |
| ② | 简写 | +828 | +232 | +1839 |
| **③ 最小集**（entities + event_date，其余留 `update`） | 详述 | **+669** | +319 | +994 |
| ③ | 简写 | +447 | +154 | +772 |

**关键读数**：**税几乎全是说明文字，不是类型。**形态 ① 详述版给 token 增量 **+893**，而整个
`mem_remember` schema 现在只有 **917** token——**等于把工具定义翻一倍**。形态 ① 简写把同一份字段压到 +383，
形态 ③ 详述 +319、简写 +154。**契约形状的选择就是这 154–893 token 的选择。**

> 一个诚实的边界：`flattenToolSpec`（DSH 面）读的是**同一批字段 schema 与同一份合并描述**
> （`mergedFieldDescription`），所以**字段的增量在两个面上相同**；这里量的是契约的单一真源
> （MCP 推导），量的是增量而不是宿主最终载荷。

### 5.4 单次写入增量（校验 + 落库）

- **校验（`safeParse`，3000 次中位）**：基线 2.6 µs；加新字段 1.2–3.9 µs；**同一 schema 在「不给新字段」时
  0.9–2.6 µs**。差异 **<2 µs/次**，在这一次测量里**与噪声同级**——诚实结论是「校验开销可以忽略，测不出方向」。
- **落库（DAO 的原语句，78 事实）**：每事实 2 个名字 **2.31 ms**、30 个名字 **11.19 ms**（**×4.8**）。

「打开新字段但一个都不给」的两次 pass：**脚本 id+分数逐字节相同 17/17、产品 `rt.recall` id+分数逐字节相同 17/17**；
`A3@0% ≡ A0` **17/17**；`A1 ≡ A0`（全部行）**32/32**。⇒ **默认路径一个字节都不动**，B1 上线不会移动 41 条冻结数字。

## 6. 三个问题的答案

1. **完美调用方能提升到什么程度？** 在**规范名不在正文里**的形态上提升很大：
   实体型 alias 形状 top-3 内 gold **0/18 → 15/18**、top1 **0/6 → 3/6**、gold 进池 **0/18 → 18/18**，
   实体袋中位宽 **28 → 2**；时间窗 top-3 **1/3 → 3/3**、平均名次 **3.67 → 1.67**。
   在**规范名已在正文里**的形态（R2-8 形状，真实库更常见）上**零位移**（top1 2/2、gold 进池 6/6 不动）。
   自指族上，A2 的实体供给修好最后 1 条 gold（5/6 → 6/6），**但分组腿在 A2 之上增益为 0**，且 filter 收窄并集。
2. **合规率与一致性衰减曲线？** 实体 alias top-3：A2 15/18 → A3-50 **6/18（40%）** → A3-25 4/18 → A3-0 0/18；
   gold 进池：18 → 7 → 4 → 0。名字噪声（A4）：gold 进池 18 → 16（10%）→ 15（30%），top-3 13–14/18，
   **不单调且衰减很浅**，因为一条主题只要还有一条事实供给就仍能被实体腿找到。
   时间窗：A3-50 保留 100%（n=3）、A3-25 **比基线更差**（0/3 vs 1/3）——**半供给可能是负收益**。
   一致性（S3）：两次标注 **43.59%** 的事实至少一个字段写法不同（折叠同义后 19.23%），
   14 条查询 **7 条返回不同 id、6 条 top-3 不同、1 条 top-1 不同**。
3. **schema 税多少？** 见 §5.2：最小集（entities + event_date）**+447 字符 / +154 token**（简写）到
   **+669 / +319**（详述）；单个 `structure` JSON **+828 / +232** 到 **+1161 / +407**；
   每字段一参 **+1095 / +383** 到 **+1638 / +893**。校验 <2 µs/次（噪声级），落库**更便宜**（链接 −92.7%）。
   每轮进上下文的宿主 20 轮要多付 **6 380–17 860** token（详述三形态；简写最小集 3 080）。

## 7. 只能生产期测：instrument 什么

**本卡给不了真实 agent 的实际合规率**（没有会话日志，也不允许评测真实 agent 的行为）。A2 是**机制上限**，
不是预期收益。上线前必须 instrument，且**这四项要一起上**：

| 指标 | 定义 | 为什么是这个 |
|---|---|---|
| **结构化覆盖率**（分字段） | 写入中带 subject / attribute / entities / event_date 的比例（`admin.stats` 暴露，不加第 9 个工具） | 直接决定 alias 形状的 recall 上限；本卡测得 50% 合规只剩 40% top-3 增益 |
| **字段一致性率** | 同一事实被 update / 被二次写入时，结构字段**逐字节**不变的比例；以及**影子再标注**（同一内容二次标注）的一致率 | S3：近端 44% 的事实至少一个字段不同，折叠同义后仍 19% |
| **规范名可匹配率** | 调用方给的实体名中，能被**查询侧抽取器**原样产出的比例（`bge-base-zh-v1.5` 类会被切词） | 契约必须定义归一化；不测这一项，覆盖率会虚高而收益为零 |
| **检索位移** | 相邻两次结构写入之间，固定查询集的 **top-1/top-3 变化条数**（本卡 S3 的口径：14 条查询里 6 条 top-3 变） | 冻结评测集与真实库分叉的早期信号 |

**门槛建议**：结构化覆盖率 **<50% ⇒ 不发布**（这一条由本卡数字直接支撑：alias top-3 增益保留 <50%）；
字段一致性率（影子再标注）**<80% ⇒ 先解决一致性**（80% 是**建议值、不是实测阈值**；S3 的 19% 实质差异已经让 6/14 查询换 top-3）。
