## 1. 口径与共同纪律

- **语料**：`VACUUM INTO` 只读快照，**85 条 active**（archived 79 只作对照）。选中规则 `status='active' AND length(content) ≥ 200` →
  **68 条**，与派单预期（85 中 68 条 ≥200）逐数字一致。选中长度：min 203 / p25 286 / **中位 346** / p75 422 / p90 516 / max 882 /
  均值 378.26 / 合计 25 722 字符；实体袋中位宽 **35**（全库 32）。
- **两遍独立拆分**：都是**独立 `dsh headless` 进程**（各自独立上下文、独立 `AVANTF_HOME`、只读 `/tmp` 输入、只写各自 `/tmp` 输出）。
  两遍互不可见（B 遍被明确要求不读 A 遍结果），约定刻意不同（A：阅读顺序、允许较细；B：反向处理、边界更保守、动词短语为主）。
  温度不可控，记为残余。
- **生产臂 identity 断言**：S2 的脚本内复现与 `rt.recall` 在**同一原子库**上逐条同序，抽检 **25/25 pass**；
  `appendLegs` 返回空数组时与「不挂任何腿」**逐字节相同**（`appendLegs_noop_identical = true`）。
  S1/S3/S5 为计数/机制卡，无检索 pass，identity 记 **N/A**（沿用 R2-5/R2-7 口径）。
- **默认不变**：关系腿只存在于 S2 两条臂；S1 臂的脚本 pass 与生产 `rt.recall` 逐字节一致（identity 25/25）。
- **隐私**：正文只在进程内读；一切从正文派生的字符串（原子文本、来源句、关系、派生问题、改写/否定探针）
  落 `/tmp/dsh-r5/`；仓库产物只有 id / 长度 / 计数 / 比率 / 分数 / 占比（§10）。
- **与派单规格的三处偏差（如实记录）**：
  1. 派单 §开头说复用 `bench-r4-fixture.mjs`——**该文件不存在**（四轮的 fixture 是 `bench-r3-fixture.mjs`；第四轮改用真实语料，
     没有 r4 fixture）。本轮因此只复用 `bench-spike-lib.mjs` + `bench-r4-lib.mjs` 的隐私/快照/运行期机制，未重造 fixture。
  2. 「同一次调用里连关系一起给出」被落成**同一批 = 同一条 source fact 的原子**（不跨 fact 连边）。理由：最终形态的写入单位是
     "agent 保存一条记忆"；跨 fact 关系需要全局命名空间，而本轮不建关系表。这是本轮**明确未覆盖**的一格。
  3. `EMBED_SIM_DUP_MAX` 在生产里不是"去重器"，而是**矛盾检测里"这是近重复、不算矛盾"的上界**。报告按这个真实语义使用它（§4）。

## 2. S1 · 拆分语料与真值

**输入**：68 条 `length ≥ 200` 的真实 active 事实（合计 25 722 字符），只落 `/tmp/dsh-r5/corpus.json`。

**产出（两遍独立）**

| 读数 | A 遍 | B 遍 |
|---|---|---|
| 原子数 | **450** | **389** |
| 关系边数 | **246** | **177** |
| 每 fact 原子数 min / 中位 / max / 均值 | 3 / **6** / **18** / 6.62 | 3 / 6 / 10 / 5.72 |
| 原子长度 min / 中位 / max / 均值 | 8 / **50** / 263 / 59.15 | 12 / 58 / 263 / 66.18 |
| 原子总字符 ÷ 原文总字符 | **1.0348** | 1.0008 |
| `source_sentence` 是原文逐字子串 | **449/450 = 99.78%** | **389/389 = 100%** |
| 有关系边的原子 | 360/450 = 80.0% | 291/389 = 74.8% |
| 关系类型分布 | `same_topic` 142 · `causal` 100 · `subsumes` 2 · `temporal` 1 · `contradicts` 1 | `same_topic` 119 · `causal` 58（其余三型 0） |

**读法（必须与裁决同读）**

1. **拆分几乎不产生新文字**：原子总字符是原文的 **1.03×**（A）/ 1.00×（B）。原因正是"自包含"要求——每条原子要把主体再写一遍，
   于是原文里靠指代省略掉的主体被补回来，抵消了拆分带来的重复。
2. **拆得比预期碎**：中位 6 条 / 最多 18 条。A 遍给 B 遍的指令是"更保守"，结果只少了 61 条原子（450→389），
   说明"该拆多少"这件事在两次独立标注之间**没有稳定答案**（§5 的一致性数字是这条的直接后果）。
3. **`source_sentence` 逐字率 99.8–100%** 只证明"拆分者没有编造来源句"，不证明原子的语义忠实（后者由 §7 的抽样判定给 8% 偏差率）。

**查询集产出（S2 的输入，全部由原子派生）**：每原子问题 **432 条**（450 条原子里 18 条被守卫否掉）；
跨原子问题 **185 条**（246 条边里由两原子各有可用 topic 的 185 条产生），其中 **149 条"关系必需"**
（第二个 gold 原子不含第一个 topic，第一个也不含第二个 topic ⇒ 单靠词法/实体腿够不到第二条）。
守卫沿用第四轮硬规则：**查询与 gold 文本共有的每个 3-gram，在原子语料里的 df 必须 ≥2**。

## 3. S2 · 质量臂：拆分割掉了 4 倍字符，也割掉了 13 个百分点的命中率

**设计**：同一个 68 条语料，只换写入形态；查询集 arm-independent（守卫在原子语料上算一次，三条臂共用）。

| 臂 | 写入形态 |
|---|---|
| **A0** | 现状：一条长事实（68 行，DB 1 466 368 B） |
| **S1** | A 遍原子（450 行，DB 6 094 848 B，**4.16×**） |
| **S2-w0.15 / w0.05** | 同一原子库 + 脚本内**一条**关系腿（权重 0.15 / 0.05；生产权重 0.55/0.30/0.15 **不做归一化**，所以该腿对候选的影响上界就是它自己的权重） |

**关系腿**：查询实体 → 携带该实体的原子（种子）→ 种子在 A 遍声明边上的邻居（对称、排除 `contradicts`），每个邻居记 1.0 分，腿内按自身最大值缩放后按权重计入。

   这是拆分唯一一处压倒性的、可兑现的收益。
3. **这不是 topic df 造成的假象**：只看 topic 在原子语料里 df≤2 的 247 条查询，A0 仍是 **124/247 = 50.2%** vs S1 **87/247 = 35.2%**。
4. **关系腿在每原子问题上是负的**：w0.15 把 top1 再压到 25.69%（比 S1 低 5.56pp）、missing 85；
   w0.05 与 S1 基本持平（top1 +0.46pp、top3 −0.93pp）。原因：关系腿按"共享实体"扩邻居，把兄弟原子推进池并抬高它们，
   而每原子问题的 gold 只是其中一条。
5. **关系腿会撑大池子**：平均池宽 7.02 → 9.51；`gold 进池` 几乎不变（430/431），说明它换的是**排序**不是**召回**。

## 4. S3 · 去重与矛盾检测：拆分让"矛盾"看得见，也让"改写"更容易被误判成矛盾

**阈值（生产原值，脚本直接 import 产量函数 `detectContradictionEmbedding`）**：
`EMBED_MIN_ENTITIES=2`、`EMBED_OVERLAP_MIN=0.5`、`EMBED_SIM_MIN=0.75`、`EMBED_SIM_DUP_MAX=0.97`。
`sim ≥ 0.97` 被读作**近重复 → 矛盾分 0**；`0.75 ≤ sim < 0.97` 且 overlap ≥ 0.5 → **上报矛盾**；`sim < 0.75` → 看不见。
`content` 是 `TEXT NOT NULL UNIQUE`，逐字重复在两种形态下都抓得到。

**探针（模型生成，23 条分层样本，每条 fact 一个锚原子 = 它最长的原子）**：`paraphrase_long`（整条原文的同义改写）、
`paraphrase_atom`（锚原子的同义改写）、`negation_atom`（明确否定锚原子断言的一句话）。

### 4.1 阈值层（23 对）

| 对 | 中位 sim | 中位 overlap | ≥0.97（近重复） | 矛盾带 [0.75,0.97) | <0.75（看不见） | 生产分 >0 |
|---|---|---|---|---|---|---|
| 长段 vs 它的改写 | **0.9795** | 0.7846 | **14** | 9 | 0 | 9 |
| 原子 vs 它的改写 | 0.9356 | 0.7647 | **5** | **18** | 0 | 17 |
| **原子改写 vs 长段**（跨粒度） | 0.7511 | **0.2571** | 0 | 12 | 11 | **0** |
| 原子 vs 它的否定 | **0.9046** | **0.7368** | 1 | 22 | 0 | **18** |
| **长段 vs 同一句否定** | 0.7645 | **0.2593** | 0 | 13 | **10** | **0** |
| 逐字重复（对照） | 1.0 | 1.0 | 23 | 0 | 0 | 0 |

### 4.2 生产写路径（真实 `rt.remember`，两张临时副本，探针分相写入）

| | 改写（同 fact） | 否定（同 fact） | 跨 fact 对照（新文本，**不该**报） | 逐字重复 |
|---|---|---|---|---|
| **整段形态** | 23 新行 / 0 逐字命中 / **5 条误报矛盾** | 23 新行 / **0 条上报** | 23 新行 / **8 条误报** | **23/23 逐字命中** |
| **原子形态** | 23 新行 / 0 逐字命中 / **13 条误报** | 23 新行 / **15 条上报** | 23 新行 / **0 条误报** | **23/23 逐字命中** |

**反例（避免把"更敏感"误当"更好"）**：跨 fact 的否定 vs 锚原子，sim 中位 **0.5932**、只有 **4.35%** ≥0.75 ⇒ 相似度带本身并不"什么都像"。
跨 fact 对照在整段形态上出现 8 条误报，是**实体 overlap 太高**（长段装了很多实体）而非 sim 太高——这正说明整段形态的误报来源和原子形态不同。

**读数**

1. **逐字去重完全不变**：`content UNIQUE` 两种形态都 **23/23** 抓到逐字重复；同义改写 **0/23**（本来就是预期）。
2. **近重复（≥0.97）判定变差**：整段 **14/23** → 原子 **5/23**。原子化把"几乎一样"推成"有点像"，落到矛盾带里。
3. **矛盾检测变好，而且不是小幅**：一句被推翻的断言嵌在长段里 **0/23** 被上报（overlap 0.2593 过不了 0.5 门槛）；
   独立成原子 **15/23** 被上报（阈值层 18/23）。第四轮"`EMBED_SIM` 对段落里单句被推翻不敏感"的推断得到直接证实。
4. **代价是误报结构换了位置**：同 fact 改写误报 **5 → 13**（更差）；跨 fact 无关文本误报 **8 → 0**（更好）。
   净效果取决于库里"同义改写"和"跨主题近邻"哪个更多——**本轮语料无法回答，这是留白**。

## 6. S5 · 批量调用的机制代价（临时库副本，脚本模拟）

**方法诚实边界**：生产没有批量 `add`，所以批量路径用**生产的准备步骤**（`tagText` → `entitiesFromTokens` /
`triplesFromTokens` / `normalizeWrite`）加**生产私有的 `persistFact`** 在一个外层事务里执行——适配器会把嵌套事务变成
`SAVEPOINT`，所以走的是真实的 行 + 实体 + 三元组 + FTS 写入，不是重新实现的 SQL。语义索引（编码）在两条路径里都在提交后逐条补。

### 6.1 一次事务 N 条 vs N 次单条（N=20，合成文本）

| | 总延迟 | 每条约 | 事务部分 | 编码部分 | WAL 增长 | 主库增长 | 返回形状 |
|---|---|---|---|---|---|---|---|
| **N 次单条**（今天） | **1189.18 ms** | 59.46 ms | （含在总里） | （含在总里） | **2 875 760 B** | 0 B | 20 个 id |
| **一个事务 N 条**（模拟） | **1109.84 ms** | — | **29.19 ms（1.46 ms/条）** | **1080.65 ms** | **1 087 680 B** | 0 B | 20 个 id |

- **事务部分快 40.7×**，但**总延迟只快 1.07×**：瓶颈是**逐条编码**（1080.65 ms），批量 API 省不掉它
  （除非把嵌入后端也批量化，那不在本轮范围）。
- **WAL 少写 2.64×**（2.88 MB → 1.09 MB）。主库文件两边都是 +0 B：WAL 模式下增长先在 `-wal` 里。
- `journal_mode = wal`（生产 pragma）。

### 6.2 部分失败语义（第 k 条违反 `content UNIQUE`）

| 语义 | 结果 |
|---|---|
| **跳过**（生产自己的行为：`INSERT OR IGNORE` + `findByContent`） | 4 条 → **3 个新行**，返回 **4 个 id**，事务**提交**；重复那条返回既有 id、`is_new=false` |
| **全回滚**（假想的裸 `INSERT`） | 第 2 条抛 UNIQUE → **整回滚，0 个新行** |
| N 次单条（今天） | 4 条 → 3 个新行，`is_new` = `[true,false,true,true]`，**从不抛错** |

**实现建议（形状问题，必须先定死）**：批量 `add` 若沿用生产的 `INSERT OR IGNORE`，语义自然是**跳过**，
与今天的单条行为一致、对调用方最不意外；"全回滚"会与现状背道而驰，并让第 k 条的一个重复废掉前面 k−1 条。

### 6.3 与既有机制的关系

| 机制 | 读数 | 判断 |
|---|---|---|
| `created_at` | 同一事务 5 行 → **1 个不同值**，非递减为真 | `CURRENT_TIMESTAMP` 是**秒**分辨率；一批同一秒内写入会**共享** `created_at`。"严格单调"不成立，只有非递减 |
| 修订链（一个事务内 A→B） | `base.status='archived'`、`next.supersedes_id=base`、`linked=true`（用 `archiveOldIfActive`） | 批量里混入 update **可以**表达，但顺序即语义 |
| `reindexEntities` | 批量后 `entities_stale_after_batch=0`；一次 sweep `{rebuilt:0, deferred:0}`、0.21 ms；预算 2000 | 批量写入**不制造**重扫债（`entities_version` 已是当前值） |
| trust 首次结算 | 5/5 行 `trust_score=0.5`（= `trust.start`）、`settle_clock` 已写、`bonus_window_at` 已写、`bonus_count=0`、`pinned=0` | 批量不改变首结语义 |

## 7. S6 · 失败模式与写侧成本

| 失败模式 | 量法 | 数字 |
|---|---|---|
| **自包含性丢失** | ① 拆分者自报 `self_contained=false`；② 启发式：原子含 18 个指代/指示词之一；③ 25 条抽样人工判定 | ① **5/450 = 1.11%**；② **63/450 = 14.0%**；③ **2/25 = 8%** |
| **过度拆分** | 25 条分层抽样，判定 `faithful / drifted / vacuous` | **23 / 1 / 1** ⇒ 背离或空洞 **2/25 = 8%**（含 1 条背离原意、1 条无信息量） |
| **孤儿原子** | 按既有 purge 行为推演：兄弟原子全被归档后单独存活是否还可理解 | **0 个 fact 只拆出 1 条原子**（每 fact ≥3 条）⇒ 结构上**每个原子都有可被独立清理的兄弟**；"只剩它自己"的场景**本轮未实测**（需要跑 purge/归档时序，属未覆盖） |
| **行数膨胀** | 85 → 85 − 68 + atoms | A：**467 行（5.49×）**；B：**406 行（4.78×）**。DB 体积（同一批源事实）**1.47 MB → 6.09 MB（4.16×）** |
| **写侧 token** | 序列化 `{facts:[{content}],relations}` ÷ 原文 | 25 723 → **47 409 字符 = 1.84×**，多花 **21 686 token/字符**（CJK ≈ 1 token/字符） |

**break-even（判据⑤）**：每次召回省下 **1042.58 − 295.88 = 746.70 字符 ≈ 747 token**；
`21 686 ÷ 747 = **29.03 次召回**` 回本。这条把"质量改善"翻译成"值不值"：
如果这套记忆一天被召回 ≥1 次，**29 天**回本；如果一周召回一次，**7 个月**。
注意这是**上界**（关系声明字符也算进了写侧成本），若不做关系层、写侧只多花不含关系的部分，回本更快。

**三条必须与数字同读的**：

1. **14.0% 的启发式不都是真丢失**：指代词出现在"该表/此项"这类**已经带名词**的用法里时仍可自包含。
   模型自报 1.11% 又明显偏低（它自己拆的、自己判自己）。人工抽样的 **8%** 是三者里最可信的一个数。
2. **行数膨胀 5.49× 会打到三处**：`stats` 的分母、清理/归档的扫描量、备份体积。DB 体积 4.16× 已实测。
3. **孤儿原子是本轮唯一"只有结构、没有读数"的失败模式**：结构风险随拆分线性放大（原子数 × 每个都可能比兄弟活得久），
   但没有跑真实 purge 时序。

## 9. 预注册判据的逐条裁决

| 判据 | 结果 | 证据 |
|---|---|---|
| **① 每原子问题 top1/top3 实质改善 且 每命中字符数下降** | **不通过**（后半成立、前半反向） | top1 −12.96pp、top3 −13.19pp、missing 12→45；字符 −75.9% |

| **③ 两次拆分关系一致率 ≥80%** | **不通过** | 边集合重合 56.52% / 64.20%；类型一致 83.65%（这一项达标，但边本身对不上） |
| **④ 没有不变量被打破** | **大体通过，含两处新代价** | 逐字去重 23/23 两形态；修订链 `linked=true`；首结 5/5 正常；`entities_version` 无债、sweep `rebuilt:0/deferred:0`；`created_at` 非递减。**但**：拆分让近重复判定 14→5、同 fact 改写误报 5→13；`created_at` 一批共享秒级值；清理/孤儿语义未实测 |
| **⑤ 给出 break-even** | **给出** | **29.03 次召回** |

**按预注册公式**：采纳需要 ①∧②∧③∧④∧⑤ ⇒ **①③ 不成立 ⇒ 不采纳「拆分 + agent 声明关系 + 一次调用」这个最终形态**。

**预注册的"条件采纳"分支也不字面适用**：它要求"**仅拆分本身有效、关系无增量**"。实测恰好相反——
**拆分在命中率上没有增量（是负的），只在字符数上有增量；关系在它自己的派生查询上有真实增量（+17.45pp），
但一致性只有 ~60%**。两个方向都不落在预注册写好的格子里。

### 9.1 事后建议（**明确标注：这不是预注册判据的结果**）

1. **不做 agent 声明的关系层**。理由有两个独立数字：① 边集合两次拆分只有 56–64% 重合；② 声明的边里 **73.98% 引擎用
   "共享实体"就能派生**，为剩下的 26%（主要是 `causal`）付整个关系面的写入成本与 +562 token 契约税，不划算。
2. **拆分不做默认、只做可选写侧自由度**：它把每次回答从 1042 字符压到 251 字符（4.1×），
   代价是 top1 掉 13pp、写侧多 1.84× token、行数 5.49×、DB 4.16×。**当"回答太长"是主诉时它值；当"找不到那条"是主诉时它亏。**
3. **如果做批量写入，就按这三条定形状**：沿用 `INSERT OR IGNORE` 的**跳过**语义（与现状一致）；
   `facts` 数组 + 可选 `relations`（下标引用，+562 token）；**单次上限 20**（本轮 max 18）。
   收益是 2.64× 更少 WAL 与 N−1 个回合；**不是** token——声明关系时参数反而多花 2164 token。
