## 2. S1 · 读取器与语料画像（无标签）

- 全 85 条 active：长度分布、实体袋宽、实体名**是否已逐字在正文中**（R2-8 已证 100%，这里按事实分组复核）、
  `created_at`/`updated_at` 分布、**可用的"事件时间"事实数**（正文明含可解析时间表达的条数）。
- **alias vs literal 形状占比**：对每条事实，构造"规范名不在正文里"的形态是否可能（例如别名/缩写/全半角/大小写变体），
  给出**可改善人群占比**——这直接决定 B1 在本语料上到底有没有生意。
- 输出：语料画像 + 形状占比表。

## 3. S2 · 影子标注（两遍独立）——真实语料上的一致性/方差

- 取样 **≥60 条**（按长度分层），对每条事实，让执行者按"如果我是写入的 agent"的要求填：
  `entities[]`（规范名）、`subject`、`attribute`、`event_date`（有则填）、`source_ref`（能归属则填，否则 null）。
- **两遍独立标注**：换提示词措辞/顺序/温度（记录两遍的差异设置）。**两遍之间不得互相看结果。**
- 指标：字段级**精确一致率**与**折叠同义后一致率**（与 R3 合成语料的 43.59%/19.23% 对照）、
  每字段覆盖率、`source_ref` 归属率（对照 R2-5 的 22.4% 路径形上界）。
- 输出：一致性/覆盖率/归属率表 + 两遍差异的例子（**例子只放 /tmp，报告只给聚合与形态描述**）。

## 4. S3 · 真实语料上的 B1 上限（alias 形状）

- 用 S2 的**第一遍标注**当"调用方供给"，在真实语料上跑：
  A0 基线（生产） vs A2 供给（按标注覆盖度 100%/50%/25%）。**用 R3 的同一套脚本口径**（entity leg + fuse）。
- 查询集：从真实事实反推的实体型查询（见 S4），分成 **alias 形状** 与 **literal 形状**两组分别报。
- 指标：top-1 / top-3 内 gold / gold 进池 / missing / 实体袋宽 / 候选扇出；**并集是否收窄**；
  **默认不变**（未供给时与 A0 逐字节相同）。
- 裁决：本语料上 alias 形状占比 × 供给合规率决定 B1 的实际预期（写清公式，不许直接用 R3 的 15/18）。

## 5. S4 · 反推查询集（E0 雏形：事实 → 问题）

- 从真实事实**反推它能够回答的问题**（自监督 gold = 该事实），要求：
  ① 查询**不得包含该事实的唯一字面**（否则词法腿单独就能答，测量变成自我实现）；
  ② 分形态：实体型 / 时间型 / 属性型 / 无时间守卫 / 无关守卫（gold 为空）；
  ③ 每条带 `must_include` 与 `must_exclude`（从同库其它事实里挑干扰项）。
- 指标（不是评测结果，是**产出率**）：每 100 条事实能产出多少条合格查询、各形态占比、
  守卫查询能否真的返回空、**碰撞率**（查询字面与某无关事实的碎片重合的比例）。
- 输出：派生引擎（代码，进仓库）+ 产出率与形态表；**派生数据落 /tmp，不进仓库**。

## 6. S5 · A2 的真实时间查询集

- 从 S4 的时间型查询里挑出**真实内容派生**的一批；测 A2 的口径沿用 R2-2（`missing / in_top3 / 名次 / 守卫误伤`）。
- 另报：真实语料里**有多少事实具备可用事件时间**（S1 已算）——这是 A2 在本语料上的**需求上界**。
- 裁决：与 R2-2 的派生查询结论是否一致；若一致 ⇒ A2 的"能力已证"，剩下的仍只是"真实用户会不会这么问"。

## 7. S6 · attribute 形态与 G-A7 归属率

- **attribute**：从事实反推"某主体的某属性"问句（如"用户的名字""项目的截止时间"），
  用 S2 的 subject/attribute 标注做**过滤腿 vs groupleg**两形态，看是否有检索收益。
- **G-A7**：用 S2 的 `source_ref` 标注给出归属率分布（按 kind 分类），并与 R2-5 的上界对照，
  给出"上生产后 `stats.facts_with_source_ref/total` 的预期区间"。

## 8. S7 · 两条无标签项（不需要标注）

1. **袋/锚点 sweep（literal 形状）**：在真实分布上扫"实体袋剪枝 / 锚点阈值 / 饱和并集参数"，
