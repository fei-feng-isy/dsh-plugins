## 2. 卡（按成本从低到高；前面的做完再动后面的）

### R2-1 F4 的正面对照 —— **最优先，最便宜**
第一轮 F4 三臂逐条同分同序，但 `fts_leg_head_differs 2/20` 而 `fused_scores_differ 0/20`。
- **做法**：在**语义腿不可用**的网络（degraded：`semDEGRADED_WEIGHTS`；冻结集里 35 条本来就是 degraded 口径）
  与**语义权重置 0 / FTS 权重置 1** 的网络上，重跑 `bm25 / coverage / hybrid` 三臂。
- **另做一张正面对照**：注入一个**必定改变排序**的改动（例如把 FTS 腿分数整体反转，或把某条腿权重从 0.3 调到 1.0
  且语义置 0），证明脚手架**能**检测到变化。
- **裁决**：三臂在 degraded 网络上**仍**逐条相同 ⇒ F4 的否决**封死**；若出现分歧 ⇒ 记录分歧查询与幅度，
  改判"仅在词法主导的网络上有效（附条件）"。正面对照必须通过，否则本卡不成立。

### R2-2 A2 的**真实语料**时间查询集（补足"0 条真实查询"）
- **做法**：不用合成语料，而是从快照里**派生**：选 `created_at` 落在某个窗口、且话题词 df 低的事实，
  用"话题词 + 窗口词"构查询（**查询里不得含该事实的唯一字面**，否则词法腿单独就能答），gold = 该事实；
  守卫 = 同话题**不带**时间词。窗口覆盖：今天/昨天/前天/本周/上周/这个月/上个月/今年/具体日期。
- **指标**：窗口腿（w0.3 / w1.0 / hard）与基线的 `missing / in_top3 / 平均名次`、守卫误伤、解析正确数。
- **裁决**：in_top3 显著改善 且 守卫误伤 0 ⇒ **条件解除**；否则 A2 维持"能造出来但没有需求证据"。

### R2-3 本仓缺陷：`gradedTerms` 的"2 字话题词 + 时间词"盲区（第一轮顺手发现）
- **假设**：`限流 上个月` 这类查询只产出时间词的 3-gram ⇒ FTS 腿看不到话题词。
- **做法**：在真实快照上枚举"含 2 字 CJK 词 + ≥3 字词"的查询形态，量：受影响的查询比例、
  该形态下 FTS 腿是否命中 gold、以及把 2 字 run 也纳入取词（`substringTerms` 同样的守卫）**在脚本里**后
  的命中变化。
- **裁决**：给出"受影响比例 + 修复后的前后对照"；**不实现**，只出数字与建议（这是既有短查询线的延伸）。

### R2-4 G 侧结构改动的"默认行为逐字节不变 + 不变量"（G-A1/A2/A6/A8）
这四项都没实现，本卡是**在快照副本上做 schema 模拟**，不是改生产。
- **G-A1/A2**：在副本上 `ALTER TABLE` 加 `valid_from/valid_to/superseded_by`，按提案规则写入标注；
  断言 ① 默认检索的 id/顺序/分数**逐字节不变**（新列不参与）；② 不变量"`superseded_by` 只出现在
  archived 或 `valid_to IS NOT NULL` 的行"可由一条 SQL 验证；③ `active + valid_to` 的行确实能出现在
  `RecallHit` 且带标注。
- **G-A6**：模拟 `assert_count`（重复 add 累计）；断言检索不受影响。
- **G-A8**：模拟受约束 `entity_type` + 越界回落；断言检索不受影响。
- **裁决**：每项给"可行 / 不可行 + 需要多少迁移与 wire 改动 + 默认不变断言是否成立"。

### R2-5 G-A7 来源覆盖率（能测多少测多少）
- 离线**测不到**"调用方愿不愿意传 `source_ref`"（没有会话日志）。**因此**：① 给出可测的上界代理——
  现库事实中，正文/实体与某个 managed kb 文档有重叠（⇒ 来源**可推断**）的比例；② 明确写出
  **生产期必须instrument的指标**（`stats`：`facts with source_ref / total`）与它的验收阈值。
- **裁决**：代理数字 + "只能生产期测（原因）"。

### R2-6 L1/B1 主体·属性 spike（成本最高的一档）
- **抽取**（规则，不调 LLM）：subject / attribute 的候选规则（例如"事实里 df 最高且重复出现的实体"=subject；
  谓词头名词=attribute），在真实库上跑一遍；**20–30 条抽样人工判定**，报 precision / coverage /
  含 `用户` 但主体不是用户的条数（点名 `用户是` 载体）。
- **查询侧**：旗舰例 `我是谁？` 用现有自指改写定 `subject=用户`；两条臂：**组内过滤（收窄）** 与
  **组作额外一腿（保并集）**。
- **指标**：gold #4 是否在组内、#103/#125 是否被排除、top-3 相关数、**并集是否收窄**；
  **反事实**：移除正文含 `用户是` 的载体后结果应回正。
- **裁决**：能在不伤 gold、不收窄并集的前提下排除命名的干扰项 ⇒ 采纳；否则 **不采纳**（用数字证明）。

### R2-7 L3 长事实分块 pilot（真模型，成本最高）
- **做法**：对 `N>512`（另跑 128 一档）的事实分块 K≤3，用**生产嵌入后端**（缓存里的 `bge-base-zh-v1.5`，
  **不下载**）生成块向量；聚合规则两种：`max-over-K` 与 `不许超过整事实自身分`。
- **指标**：目标 20 条查询 top-1/top-3；长笔记的**名次位置（不许变差）**；向量数 / RSS /
  `buildRuntime` 增量；写入延迟倍数。
- **裁决**：top-3 上升 **且** 长文位置不变差 ⇒ 采纳；否则不采纳。成本不可控时只做 pilot 并**写明未完成**。

### R2-8 A4 索引文本并入实体名/日期（临时库改 schema 形状）
- **做法**：在快照副本上新增真实列 + 第二张 external-content FTS 表（或让 `facts_fts` 指向新列），
  填入"正文 + 实体名 + 日期 token"；触发器等只建在副本上。
- **指标**：索引字节与 db 增量、`recall`/`kb_query` 的 p50 变化、"**只有实体名命中**"的查询是否改善。
- **裁决**：实体名查询改善 且 索引 <2× 且 p50 <+20% ⇒ 采纳；否则不采纳。
