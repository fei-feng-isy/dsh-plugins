# Changelog

All notable changes to `@avantf/dsh-mission` are documented here.

## [Unreleased]

### Changed（模型工具面）
- **执行者可以派生 subagent**：worker 的工具面不再拒绝 `subagent` / `subagent_fork` —— 起子 agent 是节点**内部**的
  实现手段，树只认节点与结果，收敛不受影响。`send_message` 与 goal / mission 控制类工具对 worker 仍然不可见
  （`submit_mission` 仍是唯一出口）。worker 提示词相应补了一句：要并行就派生 `subagent`，并用
  `run_in_background: false` 同步取结果。
- **工具可见性按会话角色收口**：prompt 装配现在对**每一类**会话给出它真正能用的工具集——能建树的会话不含
  执行者那 3 个、被派出的 worker 不含 owner 那 6 个、**其余会话（例如 Agent Teams 的 teammate、别的插件的
  子代理）一个 mission 工具都不含**。此前这些会话既拿不到指导段、又看得见全部 9 个工具，其中
  `create_mission` 每次都只会答 `no-authority`。注意这是**可见性**调整：注册方式与拒绝边界不变，模型若仍调用
  这些工具，答复依旧是 `no-authority` / `not-owner`。

### Changed（面板与读取）
- **任务标签的"有没有在跑"不再每次拉整棵树**：新增轻量读取 `status`，标签状态的那次兜底读（每 30 s 一次，
  用于发现静默死掉的推送流）从"拉全量快照并遍历所有树×所有节点"换成只回 `{ running }` 的短路判定。
  面板可见时的即时读取仍走全量快照。Remote 方法集合变化 ⇒ `SNAPSHOT_WIRE_VERSION` 3 → 4；老客户端问新方法
  会拿到 404，而宿主的挂载日志会列出实际发布的方法名，便于判断"哪一半旧了"。
- **大树不再一次性渲染全部行**：树内的窗口化单位从"棵树"改成"可见行"（阈值 120 行，含树头），一棵
  200 节点的活跃树（节点默认展开时）首帧只挂载窗口内的行 + overscan，而不是全部 2000–2800 个元素。
  展开/折叠、覆写、详情弹窗、复用与排队标记、缩进等语义均未改变。
- **快照帧的调试日志**：`snapshot` 的返回多带一个 `bytes`（该帧的 UTF-8 字节数，**只在调试日志里用**，
  不属对外承诺、也不进 schema），客户端在 `console.debug` 里记下每帧的 `bytes` 与 `safeParse` / 合并耗时，
  用于判断是否值得做增量快照。

### Fixed
- **卸载插件不再给在途派发记一次"启动失败"**：插件卸载会中止在途派发，此前这条中止与真正的启动失败走同一条
  路径——节点被记一次 `spawnFailures`、进冷却，日志还写成 `dispatch of … failed`；反复重载足以把一个节点推向
  失败上限并触发一次误导性的"反复出过问题"上报。现在卸载期的中止被单独识别（沿 `cause` 链判定），节点回到
  待派发、不扣任何预算、日志降级为信息级并写明是卸载。
- **`unit` 范围互相包含时 owner 会收到提醒**：`unit` 的互斥语义不变（仍是精确匹配的引擎强制租约），但当两个
  同时运行中的节点声明了互相包含的范围（例如一个 `pkg/a`、一个 `pkg/a/b`）时，owner 会收到一条一次性提醒，
  指出两个节点与各自的 `unit`，并建议把其中一个写成另一个或改窄。纯提示：不改调度判定，也不改任何节点的状态。
