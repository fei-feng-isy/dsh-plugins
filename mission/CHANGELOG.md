# Changelog

All notable changes to `@avantf/dsh-mission` are documented here.

## [Unreleased]

## [0.4.5] - 2026-10-19

### Fixed
- **没有 typert 注册表的宿主上不再"静默消失"**：`typert` 原来写在 cordis 的 `inject` 列表里，而那里每一项都是
  **必供**——一个自己组合插件树、不带注册表的宿主会让本插件**永远不挂载**（fiber 一直 PENDING，一行日志都没有），
  与契约里"typert 可选"以及"任务视图会说明缺了什么"两处设计正好相反。现在注册表改为 `ctx.inject` 等待：
  引擎、工具、面板照常挂载，只有浏览器半边的 Remote 命名空间缺席，任务视图如实报告。基于 `dsh-base` 的
  profile（web / headless / tui）本来就带注册表，那些环境里的行为**与之前完全一致**。
- **在 dsh 0.2.1-rc.2 上可以正常构建与运行**：该版本把内部 zod 的声明从 `^4.4.3` 改成精确 `4.4.3`（于是
  宿主公开类型面用的是 4.4.3），本仓此前只按旧宿主的 4.6.7 校验过，域表的类型边界会直接报不兼容。现在在边界
  上做一次显式类型桥接，两代宿主（4.4.3 / 4.6.7）都能通过；运行时不受影响。

### Changed
- 测试替身可以扮演两种 `subagents` 启动形态（默认 `startActivation`，即 0.2.1 的形态），派活路径在两代宿主上
  都有覆盖；`toolFilter` 相关的用例显式钉在旧形态上。

## [0.4.4] - 2026-10-19

### Fixed（向上兼容：新宿主不再拒载）
- **dsh 在 0.2 条线内把 `subagents.startContinuable` 并进了 `startActivation`**（后者要求
  `delivery: 'parent' | 'caller'`）。旧契约把 `startContinuable` 声明为必供方法，所以在那个宿主上插件
  整棵**拒载**（`INCOMPATIBLE — required service "subagents" is mounted but exposes no
  startContinuable`），任务标签、命令、提示词段全部不工作。现在启动方法改为**挂载时探测**：
  有 `startActivation` 就用它（带 `delivery: 'parent'`，语义等同原来的 continuable 子会话），
  只有 `startContinuable` 就用它；`sendMessage` / `interrupt` 仍是必检方法（两版签名一致）。
  两个宿主上插件都正常挂载，派活路径各自可用。
- **宿主连启动方法都没有时不再整棵拒载**：插件照常挂载（树、面板、命令、提示词段都在），并在启动日志里
  报一条 ERROR；每次派活会明确说明"这个宿主无法启动 worker"，而不是静默卡住。这与其他环境故障的降级口径
  一致——只有被证实的不兼容才拒载，且拒载的粒度收窄到真正用不了的那条路径。

### Changed（新宿主上的 worker 可见性）
- **新宿主的启动契约不再接受 `toolFilter`**（已改用 Agent Preset 表达），所以在那上面 worker 看到的工具
  由它的 preset 决定，不再由本插件的 deny 列表收窄；启动日志会有一条 WARN 说明这一点。**边界没有放松**：
  越权调用仍由工具自身的授权判定拒绝，任务树的收敛不依赖"看不见"。在仍带 `toolFilter` 的宿主
  （含当前已发布的 dsh 0.2.0-rc.2）上行为与之前**完全一致**。

## [0.4.3] - 2026-10-12

### Changed（模型工具面）
- **执行者可以派生 subagent**：worker 的工具面不再拒绝 `subagent` / `subagent_fork` —— 起子 agent 是节点**内部**的
  实现手段，树只认节点与结果，收敛不受影响。`send_message` 与 goal / mission 控制类工具对 worker 仍然不可见
  （`submit_mission` 仍是唯一出口）。worker 提示词相应补了一句：要并行就派生 `subagent`，并用
  `run_in_background: false` 同步取结果。
- **工具可见性按会话角色收口**：prompt 装配现在对**每一类**会话给出它真正能用的工具集——能建树的会话不含
  执行者那 3 个、被派出的 worker 不含 owner 那 6 个、**其余会话（例如 Agent Teams 的 teammate、别的插件的
  子代理）一个 mission 工具都不含**。此前这些会话既拿不到指导段、又看得见全部 9 个工具，其中
  `create_mission` 每次都只会答 `no-authority`。注意这是**可见性**调整：注册方式与拒绝边界不变，模型若仍调用
  这些工具，答复依旧是 `no-authority` / `not-owner`。

### Changed（面板与读取）
- **任务标签的"有没有在跑"不再每次拉整棵树**：新增轻量读取 `status`，标签状态的那次兜底读（每 30 s 一次，
  用于发现静默死掉的推送流）从"拉全量快照并遍历所有树×所有节点"换成只回 `{ running }` 的短路判定。
  面板可见时的即时读取仍走全量快照。Remote 方法集合变化 ⇒ `SNAPSHOT_WIRE_VERSION` 3 → 4；老客户端问新方法
  会拿到 404，而宿主的挂载日志会列出实际发布的方法名，便于判断"哪一半旧了"。
- **大树不再一次性渲染全部行**：树内的窗口化单位从"棵树"改成"可见行"（阈值 120 行，含树头），一棵
  200 节点的活跃树（节点默认展开时）首帧只挂载窗口内的行 + overscan，而不是全部 2000–2800 个元素。
  展开/折叠、覆写、详情弹窗、复用与排队标记、缩进等语义均未改变。
- **快照帧的调试日志**：`snapshot` 的返回多带一个 `bytes`（该帧的 UTF-8 字节数，**只在调试日志里用**，
  不属对外承诺、也不进 schema），客户端在 `console.debug` 里记下每帧的 `bytes` 与 `safeParse` / 合并耗时，
  用于判断是否值得做增量快照。

### Fixed
- **卸载插件不再给在途派发记一次"启动失败"**：插件卸载会中止在途派发，此前这条中止与真正的启动失败走同一条
  路径——节点被记一次 `spawnFailures`、进冷却，日志还写成 `dispatch of … failed`；反复重载足以把一个节点推向
  失败上限并触发一次误导性的"反复出过问题"上报。现在卸载期的中止被单独识别（沿 `cause` 链判定），节点回到
  待派发、不扣任何预算、日志降级为信息级并写明是卸载。
- **工具改为按会话角色注册（不再是全局注册 + 运行时拒绝）**：能建树的会话在自己的作用域里装 owner 那 6 个、
  被派出的执行者装 executor 那 3 个、**其余会话一个都不装**（此前是 9 个全局注册，谁都能"看到"、调用时再被拒）。
  子会话因此不再为用不上的工具描述付 token，也不再有注定失败的调用路径；`unit` 与派发过滤器不再命名那些
  作用域内才存在的工具，所以不会再刷出"filter 无法命名 X"的告警。可见性仍是可用性层面的事，越权调用照旧被拒。
  需要底座 `@avantf/dsh-plugin-base` 的接口世代 **v4**（`verifyRegisteredFaces` 多了一个可选的作用域入参）。
- **一个会话装不上工具面时会说为什么**：按作用域注册要求该会话能取到作用域内的工具注册表；若某个组合里取不到
  （或拿到的是会话形状的替身），此前是**静默跳过**——那个会话于是**一个 mission 工具都没有**，而日志里只有一句
  "按角色装了 9 个工具"，看不出差别。现在这种会话会被点名（一条 `compat:` WARNING：哪个会话、哪个面、几个工具
  没装上、结果是"这个会话没有 mission 工具"）。想清楚再降级：装配瀑布只做**过滤**，它能藏起已经注册的工具，
  但变不出没注册的，所以这里必须响。本来就不该有工具面的会话（teammate、别的插件的子代理）不算降级，不报。
- **`unit` 范围互相包含时 owner 会收到提醒**：`unit` 的互斥语义不变（仍是精确匹配的引擎强制租约），但当两个
  同时运行中的节点声明了互相包含的范围（例如一个 `pkg/a`、一个 `pkg/a/b`）时，owner 会收到一条一次性提醒，
  指出两个节点与各自的 `unit`，并建议把其中一个写成另一个或改窄。纯提示：不改调度判定，也不改任何节点的状态。
