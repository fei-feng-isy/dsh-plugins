# 接口冻结与接口版本

> **这份文档说什么**：`@avantf/dsh-plugin-base` 的**公开接口**由什么构成、怎么把它冻成一件可机械检查的
> 事实，以及版本号该表达什么 —— 接口变了（不兼容）／行为或流程变了（兼容）／只是修了 bug。
>
> **不是什么**：不是**已实现**的说明。本文档 §7 逐条列出"已有 / 待做"，读代码前先看它，不要把这些规则当成
> 今天的运行行为。本文档住在仓库里（base 的 npm 产物只带 `dist` + README），面向使用者的那一句契约写在
> `../README.md` 的「版本承诺」。
>
> **两件把它逼出来的事**：① `0.1.0 → 0.2.0` 那次，两个插件必须**同批**改 peer 与 `supportedRange` ——
> 因为 0.x 的 caret 不跨 minor，"base 单独修好共享代码"在运行期与安装期都不成立；② `resolveDataHome`
> 的**语义**变过一次而名字没变（"插件 profile 的 `dataHome` 该放哪个 slot"），数据根因此换了目录，而
> 名字面快照与类型系统都抓不到它 —— 接口不只是名字。

---

## 1. 版本号要说什么

让"接口没变"成为一件**可机械检查**的事实，于是版本号能表达三件不同的事 —— 接口变了（不兼容）、
行为/流程变了（兼容）、只是修了 bug。

| 变更 | base 版本 | 插件是否必须同批改 | 载体 |
| --- | --- | --- | --- |
| **接口**：`.` 的导出集合、类型形状、顺序敏感参数的 slot 含义、语义契约 | **major**（1.0 → 2.0） | 是 | `INTERFACE_VERSION` + `api/interface-v2.json` |
| **业务流程 / 可观察行为**（插件测试断言的那些） | **minor**（1.0.0 → 1.1.0） | 否 | 无（行为即契约） |
| **纯修复**，无可观察变化 | patch | 否 | 无 |

## 2. 接口面由三层构成，三层都要冻结

1. **名字面** —— `.` 的导出（值 + 类型）。**今天已经**由 `test/public-surface.spec.ts` 的 equality
   白名单钉住（`missing === []` 那种子集断言抓不到"多导出了一个"）；`./internal` 是内部件，不在面上。
2. **形状面** —— 类型签名与参数形状。今天靠插件 `import type` 加 `typeof import('@avantf/dsh-plugin-base')`
   定型**间接**保证（签名一变插件 typecheck 就红 —— `0.1.0 → 0.2.0` 那次 work 被迫改 `promptDir` 就是它
   在起作用）。
   要改成 base 拥有一个接口类型（如 `BaseRuntimeV1`），插件只 `import type` 它 —— 今天插件用的是
   **整个命名空间类型**，等于"base 导出什么都能用"。
3. **语义面** —— 函数"做什么"的契约（数据根的层序、prompt 文件的 ensure/read/fallback、
   `compatReport` 的结构、provisioner 的终态与 `code`…）。这一层**机器抓不到**，所以只能靠两条写法
   规则（§4）+ `DESIGN.md` §7 的协议面版本表 + 插件自己的测试来钉。

## 3. 接口版本与运行期门禁

计划：base 导出 `INTERFACE_VERSION = 1`（整数）；插件构建时把它 bake 进产物，启动时与**加载到的 base**
报出的值比对，不同才告警/按能力降级。

为什么不用包版本当运行期的门：包版本每次发版都动，拿它当门会让 patch/minor 也告警 —— 今天
`supportedRange` 正是如此。接口编号只在换代时动，于是"base 单独修好共享逻辑、插件零改动"在运行期也
成立。包版本仍然有用，它是**安装期**的门（插件 peer 区间）。

## 4. 两条写法上的硬规则（都是踩过的）

- **顺序敏感的语义必须用具名对象承载。** 反例：`resolveDataHome(explicit, env, common)` —— 名字没变、
  参数个数也是三个，但"插件 profile 的 `dataHome` 该放哪个 slot"一变，数据根就变了；名字面快照与类型
  都抓不到，只有人读 diff 才能发现。正例：`compatReport(verdict, words)`。规则：只要**参数顺序**或
  **某个 slot 的含义**是契约的一部分，就改成 `{ … }` 对象 —— 形状一变，快照门禁与类型都会报。
- **可观察的文案归调用方。** `compatReport` 的尾行曾是硬编码中文 —— 一个发布到 registry 的通用包不该
  替调用方决定语言。接口里只留结构，措辞由调用方传入（现在它由 `words.logPointer` 提供）。

## 5. 冻结怎么执行：快照 + 门禁

1. `api/interface-v1.json` 记录三样：`.` 的值名、类型名、两者的 sha256。
2. 门禁（进 `release:check` 或 `version:check`）：代码里实际的导出集合必须与该 json **完全相等**。
   不等时只有两条路 —— 把误加的导出删掉，或新增 `interface-v2.json` 并把 `INTERFACE_VERSION` 加一
   （接口变更）。
3. 于是"接口变了"必然在 diff 里出现一个数字，评审看得见；`public-surface.spec.ts` 的白名单从"测试里的
   常量"变成"由快照文件驱动"，两者不会各说一套。

## 6. 走到 1.0.0 是前提，不是装饰

0.x 的 caret **不跨 minor**（`^0.2.0` 不接受 0.3.0），所以留在 0.x 时"只发 base 就修好共享代码"只对
patch 成立 —— 0.1.0 → 0.2.0 就逼着两个插件同批改 peer 与 `supportedRange`。到了 `1.0.0`，`^1.0.0`
自动吃掉 1.x 的 minor/patch，§1 那张表里"插件必须同批改 = 否"那两行才真正成立。

代价要认：冻结点之后内部重构要绕开 `.` 面，接口换代要走弃用周期。**现在是最便宜的时机** —— 消费方只有
本仓两个插件，且合并后的它们尚未发布（npm 上的 `@avantf/dsh-mem@0.1.1` / `@avantf/dsh-work@0.1.0`
是合并前的旧产物，peer 还指向已死的 `@avantf/dsh-envinit`）。

## 7. 实现清单：已有 / 待做

| 块 | 状态 |
| --- | --- |
| `.` 名字面的 equality 白名单、`./internal` 隔离 | 已有（`test/public-surface.spec.ts`） |
| 插件对 base 的 `import type` 与模块定型（签名变化 ⇒ 插件 typecheck 红） | 已有 |
| `DESIGN.md` §7 的四张协议面版本表（item / layout / status / declared） | 已有 |
| `INTERFACE_VERSION` 与插件的构建期 bake + 运行期比对 | **待做** |
| `api/interface-v*.json` 快照与"变了就必须升编号"的门禁 | **待做** |
| 接口类型 `BaseRuntimeV1`（插件改 `import type` 它，不再用整个命名空间类型） | **待做** |
| `resolveDataHome` 改具名对象（§4 第一条） | **待做** |
| 运行期门禁从"包版本区间"改成"接口编号" | **待做** |
| `1.0.0`（§6） | **待做** |

**落地顺序**（前两步是后面几步的前提：形状不先收成对象，"语义"就永远抓不到）：

1. `resolveDataHome` 改具名对象（§4 第一条）—— 唯一一处需要改形状的接口，改完语义才进入可检范围。
2. base 拥有接口类型（`BaseRuntimeV1`），两个插件改用 `import type` 它，不再用整个命名空间类型。
3. `api/interface-v1.json` 快照 + "变了必须升编号"的门禁（§5）。
4. `INTERFACE_VERSION` 与运行期门禁换轴（§3）。
5. 走 `1.0.0`（§6），插件的 peer 变成 `^1.0.0`；此后 base 的 minor/patch 自动送达。
